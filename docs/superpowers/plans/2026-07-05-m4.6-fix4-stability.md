## Task 1 — A1 exe 进程残留 + 第二实例体验

**Files**：`app/windows/runner/main.cpp`

**Background**：named mutex 单实例锁导致 argv 空的二次启动直接退出；进程不退出时 mutex 永远 ALREADY_EXISTS。

**Steps**：
- [ ] T1.1：在 `wWinMain` 末尾 message loop 退出后，立即 `::ExitProcess(EXIT_SUCCESS)`（在 `if (mutex) CloseHandle(mutex);` 之前）。这保证无论 Flutter engine 是否优雅 dispose，进程都会终止。
- [ ] T1.2：修改 `FindZhiYueWindow` 回调，**找到目标窗口后先 `SetForegroundWindow(hwnd)` + `ShowWindow(hwnd, SW_RESTORE)`**，再 `WM_COPYDATA`（如果 argv 非空）。
- [ ] T1.3：第二实例 `argv_utf8` 为空时，也执行 `EnumWindows(FindZhiYueWindow, ...)` 让已有窗口前置（之前 argv 空直接退出，是 bug）。

**Verification**：
- [ ] 手动：双击 exe → 关闭窗口 → 任务管理器观察 zhiyue.exe 消失（5 秒内）→ 再次双击能启动新实例
- [ ] 手动：双击 exe（保持运行）→ 再次双击图标 → 已有窗口前置到前台

## Task 2 — A2 PDF widget 稳定化

**Files**：`reader_engine_pdf_view/lib/pdf_renderer.dart`

**Background**：每次 build 重建 PdfViewerParams + FutureBuilder 包装导致 pdfrx 频繁 reload，N 页后内存压力 → loading 卡死。

**Steps**：
- [ ] T2.1：把 `_scannedFuture` 在 `openFile` 时启动（不只 `build` 时 `??=`），完成后 setState 写 `_scannedCache`。`build()` 同步读 `_scannedCache` 决定分支，**移除 FutureBuilder**。
- [ ] T2.2：把单页 `PdfViewer.data` 的 `params` 提取为方法 `_buildMainParams()`，**不每次闭包重建 _currentPage**——`buildContextMenu` 用 pdfrx 自带的 `params.a?.page.pageNumber`，fallback 改为 1（PD Fcontext menu 必有 anchor）。
- [ ] T2.3：PdfViewer 加 `key: ValueKey('pdf-main-${doc.sourceName}')`，确保同书 State 复用、切书干净重建。
- [ ] T2.4：`build()` 顶层包 `RepaintBoundary`，与父级 reader_body 隔离。
- [ ] T2.5：双页 `_buildDualPage` 同样处理（PdfViewerParams 方法化、key 加 #L/#R）。

**Verification**：
- [ ] 单元测试：`pdf_renderer_params_stable_test.dart`——构造 PdfRenderer，模拟多次 build（同一 doc），断言 PdfViewer widget key 稳定不变、PdfViewerParams 实例同一引用。
- [ ] 手动：打开 PDF，连续翻 30+ 页，验证不卡 loading。

## Task 3 — A3 MD 移除强制 hard break

**Files**：`app/lib/services/markdown_book_loader.dart`

**Background**：`_preserveLineBreaks` 给每行加两空格强制 `<br>`，违反 CommonMark 段内合并语义，导致段落断行堆叠。

**Steps**：
- [ ] T3.1：删除 `_preserveLineBreaks` 方法（line 134-166）+ `_isStructuralLine` 方法（line 171-189）。
- [ ] T3.2：`_markdownToHtml` 改为直接 `md.markdownToHtml(body)`（line 117-119）。
- [ ] T3.3：删除相关注释（line 105-116、121-133、168-170）。

**Verification**：
- [ ] 单元测试：`markdown_book_loader_no_force_break_test.dart`：
  - 输入 `第一行\n第二行\n\n第二段` → HTML 应为 `<p>第一行\n第二行</p><p>第二段</p>`（段内合并，无 `<br>`）

  - 输入 `- 列表项1\n- 列表项2` → `<ul><li>列表项1</li><li>列表项2</li></ul>`（结构行不受影响）

## Task 4 — A4 MD 移除图片渲染

**Files**：`app/lib/services/markdown_book_loader.dart`

**Background**：fwfh HtmlWidget 默认渲染 `<img>`，但 MD 无 base URL 时 src 当网络 URL，loading 图标/异常显示。第二章"标题变图片"很可能就是 `![...](url)` 在 fwfh 里渲染成了图片占位。

**Steps**：
- [ ] T4.1：在 `_markdownToHtml` 后用 html parser 移除所有 `<img>` 标签（替换为 alt 文本或空）。
- [ ] T4.2：实现 `_stripImages(String html)`：用 `html` 包（项目已依赖 `html/dom.dart`）解析，遍历移除 `img` 节点（保留 alt text 作为文本节点）。
- [ ] T4.3：更新 `_markdownToHtml` 调用 `_stripImages(md.markdownToHtml(body))`。

**Verification**：
- [ ] 单元测试（合并到 Task 3 测试文件）：
  - 输入 `![alt text](https://example.com/x.png)` → HTML 不含 `<img`，含 `alt text` 文本
  - 输入 `# 标题 ![icon](icon.png)` → HTML 不含 `<img`，标题文本含 "icon"
- [ ] 手动：用户报告的 MD 第二章标题不再变图片

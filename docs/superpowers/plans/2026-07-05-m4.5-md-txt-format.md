## Goal
新增 `.md` / `.txt` 书籍格式，复用 EPUB 的 HTML 渲染管道，行为与 EPUB 一致。

## Architecture（决策见 spec §4）
- **A1**：抽 `HtmlChapterSource` + `EpubxRenderer._chapters` 格式无关数据源（EPUB 零回归）
- **A2**：MD/TXT 加载器（markdown 包 / 分段包 `<p>`）
- **A3**：MD/TXT 复用 `ConcreteEpubReaderEngine`（reader_body 的 `is` 检查零改）
- **A4**：`markdown: ^7.0.0` 依赖

## Lessons
- **集成测试抓住真实 bug**：`openChapters` 漏填 `_toc` 与 M4/Q-TOC 的 PDF 目录转圈完全同构。若没写集成测试，这个 bug 会等到用户手动测试才发现。印证「集成测试 > 单元测试 > 手动测试」的优先级。
- **「最小侵入」优于「架构理想」**：原计划 A1 想抽独立 `HtmlChapterReaderEngine` 基类（重构 1211 行 EpubxRenderer，R1 高风险）。实施时发现「让 EpubxRenderer 支持两种数据源（_book + _chapters）」更简单——EPUB 路径零改动，MD/TXT 走新入口，且 reader_body 的 12 处 `is` 检查天然兼容。风险大幅降低。
- **三元地雷的危害**：5 处「未知格式默认 PDF」的 ternary 是隐蔽陷阱——加 enum 值后若不逐个修，MD/TXT 会被静默当 PDF 处理然后崩溃。集中映射（BookFormatDb 扩展）是根本解。

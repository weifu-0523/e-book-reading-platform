## 3. Scope（16 task）

### Refactor（无行为变更）

#### T1: `Book.fromRow` helper（M2）
**问题**：`BookDetailPage._retryWithBookLookup` 与 `LibraryPage.handleImportResult` 各自手工重建 `Book`（同 11 字段映射）；新加字段需双改。
**方案**：在 `app/lib/data/models/book.dart` 加 `factory Book.fromRow(BookData row)` 或 `Book.fromDrift(BooksCompanion row)`，两处调用替换。
**验收**：2 处调用点替换；新增单元测试覆盖 11 字段映射。

#### T2: BookDetailPage i18n（M3）
**问题**：`book_detail_page.dart` 10+ 处硬编码中文（"书籍详情"/"查看笔记"/"重新预处理"/"AI 导读"/"删除"/"未找到书籍"/"作者："/"格式："/"文件大小："/"添加时间："/"最近阅读：" 等），EN 用户体验破裂。
**方案**：
- 在 `app/lib/l10n/app_zh.arb` + `app_en.arb` 新增对应 key（前缀 `bookDetail*`）
- 跑 `flutter gen-l10n`
- `book_detail_page.dart` 全部硬编码字符串替换为 `AppLocalizations.of(context).xxx`
**验收**：手动切换 EN/ZH 双语正常；现有 widget test 全过。

#### T3: Shared http client provider（M4）
**问题**：`ai_guide.dart` / `open_ai_compatible_client.dart` / `web_dav_client.dart` 各自 `http.Client()`（已支持可选注入但无共享源）。每次 Q&A 请求重建 client，丢连接池。
**方案**：
- 新建 `app/lib/core/http_client_provider.dart`：`final httpClientProvider = Provider<http.Client>((ref) => http.Client());`
- `app_providers.dart` 三个 service 工厂函数 `ref.read(httpClientProvider)` 注入
- `dispose` 时 close（ProviderScope override 处理）
**验收**：provider test 验证三个 service 拿到同一 instance；现有 service test 全过。

#### T4: Provider 一致性（M5）
**问题**：`bookPreprocessControllerProvider` / `qaHistoryDaoProvider` 用 NoOp default，`qaControllerProvider` 用 `throw UnimplementedError`。生产代码漏 override 时行为不一致。
**方案**：**`qaControllerProvider` 改 NoOp default**，与另外两个对齐。NoOp 行为：所有方法返回空/初始状态，不抛异常。
**理由**：v0.9.1 已用 NoOp 模式交付 `qaHistoryDaoProvider`，用户接受；widget test 不需要每次 override；production 漏 override 在 first call 时 silent fail 比抛异常更易调试（stack trace 在调用点而非 provider 构造）。
**验收**：现有 qa dialog test 全过；新增测试覆盖 NoOp 默认行为。

#### T5: ai_summaries 防御性 cache（M6）
**问题**：`book_preprocessor.dart` `_phase2Summarize` 无条件对每章调 `aiGuide.run(...)`，仅靠 AiGuide 内部 cache 防重。如 AiGuide cache 逻辑变动，会沉默重计费 LLM。
**方案**：`_phase2Summarize` 调用 `aiGuide.run` 前，先 `aiSummariesDao.findBySourceHash(sourceHash)` 检查；hit 则跳过。
**验收**：新增测试 "已 cache 章节不调 LLM"（mock aiGuide.run 计数）；现有 preprocess test 全过。

#### T6: TOC 渐进 ✓ 标记（M1）
**问题**：`toc_drawer.dart` `_buildMarker` 仅在 `state.status == done` 时渲染 ✓，spec §5.1 期望 chunking/summarizing 期间渐进显示。
**方案**：每章查 `aiSummariesDao` 是否有该章 cache；有则渲染 ✓，无则渲染空。状态为 done 时所有非失败章 ✓。
**验收**：widget test 覆盖三种状态（chunking 中部分 ✓ / summarizing 中部分 ✓ / done 全 ✓）。

#### T7: Lint 清理（M7）
**问题**：`dart analyze` 41 项需清理（warnings 15 + lib info 26）。
**范围**：
- Warnings 15：14 in test（unused imports/vars/params）+ 1 in lib（database_connection.dart unused import）
- Lib info 26：8 deprecated_member_use, 5 use_super_parameters, 5 unawaited_futures, 2 unnecessary_import, 2 depend_on_referenced_packages, 4 others（prefer_const / dangling_library_doc_comments / cascade_invocations）
- Test info 142 不动（const/cascade 风格冗余，ROI 低）
- Vendored error 15（epubx_patched）不动
**验收**：`dart analyze` 在 app/lib + app/test 范围内 0 warning, 0 error（info 可保留）。

### Reader 重构

#### T8: `reader_page.dart` 机械拆 5 文件
**问题**：reader_page.dart 772 行，超 spec ≤300 上限。
**方案**：按既有 widget 类边界机械拆，**不引入 MVVM 重写**：
- `reader_page.dart`：保留 `ReaderPage` + `_ReaderPageState`（顶层 wrapper，~100 行）
- `reader_body.dart`：抽出 `_ReaderBody` + `_ReaderBodyState`（build 方法 + 生命周期，~250 行）
- `controllers/reader_action_handlers.dart`：抽出 20+ handler 方法为 mixin on `_ReaderBodyState`（~250 行）
- `widgets/reader_progress_bar.dart`：抽出 `_ReaderProgressBar`（独立 widget，~50 行）
- `widgets/reader_typography_panel_trigger.dart`：抽出 `_TypographyPanelTrigger`（独立 widget，~70 行）
**风险缓解**：
- T8 启动前先跑完整 reader test suite（69+36 测试）作 baseline
- 拆分后必须 0 regression
- git diff verify 仅文件移动 + import 调整 + mixin 粘合代码
**验收**：5 文件全部 ≤300 行；既有 reader test 100% 通过；golden test 视觉无变化。

### UX 三态

#### T9: 抽 `LoadingView` / `EmptyView` / `ErrorView` 公用组件
**问题**：library/reader/notes 等 page 各自实现 loading spinner / empty hint / error message，风格不一致。
**方案**：新建 `app/lib/widgets/`：
- `loading_view.dart`：`LoadingView({String? hint})` → Center(CircularProgressIndicator + optional hint)
- `empty_view.dart`：`EmptyView({required String hint, IconData? icon})` → Center(Column[icon, hint])
- `error_view.dart`：`ErrorView({required String message, VoidCallback? onRetry})` → Center(Column[icon, message, retry button])
**验收**：widget test 覆盖三组件各参数组合。

#### T10: 应用到主 5 页
**范围**：library_page / reader_page (error states) / notes_page / search_page / settings_page
**方案**：每页 audit 三态覆盖，缺失的补上，重复的实现替换为公用组件。
**验收**：每页 widget test 覆盖 loading/empty/error 三态。

#### T11: 应用到其余 5+ 页
**范围**：sync_status_page / sync_credentials_page / book_detail_page / font_management_page / ai_guide_sheet / qa_ask_dialog
**方案**：同 T10。
**验收**：同 T10。

### 新基础设施

#### T12: Windows native smoke test
**问题**：M8 单实例 mutex + WM_COPYDATA deeplink 完全无测试，bus factor = 1。
**方案**：
- 新建 `windows/runner/test_main.cpp`：含 `int main()` + 一组 `assert()` 验证：
  - Mutex 名字一致性（与生产代码 `CreateMutexW` 名字一致）
  - `EnumWindows` callback 逻辑（窗口标题匹配）
  - `WM_COPYDATA` 解析（COPYDATASTRUCT 解 deeplink string）
- 抽出生产代码可测函数（如 `ParseDeepLink(LPCWSTR)` → `std::wstring`），test_main 调用
- 新建 `windows/runner/test_main.bat`：cl 编译 test_main.cpp + 运行 + 检查 exit code
- CI bash 调用 bat，exit 0 = pass
**风险缓解**：
- test_main.cpp 独立编译，不依赖 Flutter build
- 编译输出到 ASCII 路径（`/c/dev/zhiyue-smoke/`）避免 GBK 冲突
- 不引入 GoogleTest（R5 已知中文路径 + nuget 痛点）
**验收**：本地手动跑 `test_main.bat`，exit code 0；CI 跑同样 bat。

#### T13: `docs/maintainers-runbook.md`
**问题**：M0-M8 + Phase 2 Spiral 1-5 的 setup/构建/release 知识全在 memory 文件，新 Claude 实例无法 cold start。
**方案**：写中文 runbook，章节：

- 子代理派遣规则（model 选择 / 必填项）
- 测试运行（`flutter test --concurrency=1` / 单 test 命令）
- Git 工作流（Gitee remote / commit HEREDOC / 推送纪律）
- Release 流程（version bump / CHANGELOG / Gitee Release / Windows installer）
- 常见 bug 修复（Stream.timeout 坑 / drift DAO mocking / etc.）
- 性能 baseline 测量方法（trace-startup / PerformanceOverlay / DevTools Memory）
**验收**：从 memory 文件 + 现有 docs 沉淀；新 Claude 实例读完能复现 setup。

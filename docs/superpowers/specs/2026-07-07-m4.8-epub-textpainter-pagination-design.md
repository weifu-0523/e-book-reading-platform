## 1. Context（为什么做这次引擎切换）

### 1.1 上一轮的死结

M4.6-fix20 已用 7 轮尝试（fix12→17 + Solution A 整页测量 + Solution B 渲染层兜底）证明 fwfh 在分页模式下不可救药。根因经逐字测试锁定：

```
单段独立测量高度:  81.0 px（RenderedHtmlMeasurer 用 fwfh 渲染单段）
整页实际渲染高度:  128.0 px（_buildPaged 用 fwfh 渲染该段所在整页）
drift:             -47.0 px（58% undercount）→ 末段被吃掉
```

drift 的物理来源：fwfh 在不同 layout 上下文（单段 Column vs 整页 Padding）下，其内部 `_PreferredCellStyleVisitor` / `flattened` 树等机制产生不同布局结果。即使 fix17 把首行缩进、图片高度、customStyles 完全对齐，drift 仍存在。

### 1.2 fwfh 上游确认（issue #138，2020-03 开至今 Open、`help wanted`、无人接手）

作者 daohoangson 明确不知道如何做分页。社区开发者 getBoolean 总结：

> *"The crux of the problem is that we need to know the height of the widget **before it is rendered**, but this is inherently orthogonal to Flutter's layout system."*

**结论**：升级 fwfh 0.16+ 也不会解决（架构性缺陷）。

### 1.3 业界工业级共识（来自 M4.7 调研）

| 项目 | 分页机制 |
|---|---|
| epub.js / Readium / foliate-js | **CSS columns**（浏览器排版引擎做分页） |
| cosmos_epub 1.0.0 | **TextPainter + computeLineMetrics**（抛弃 flutter_html）|
| Neat Reader（商业版） | Readium R2 → CSS columns |
| Apple Books / 微信读书 | 系统原生 + CSS columns |

两条可行路径：
- **A1**：让浏览器排版引擎做分页（CSS columns）—— 工业级稳定，但 Windows 桌面无现成 Flutter 包
- **A2**：用 TextPainter 量高 + Text.rich/SelectableText.rich 渲染 —— 测量与渲染同源，drift 归零

### 1.4 本 spec 的决策

**主推 A2（TextPainter 自绘）**，A1 留作长期备选。理由见第 5 节 AD1。

## 2. Goals / Non-Goals

### Goals

- **G1**：彻底根治 EPUB 分页底部溢出（M4.6-fix20 锁定的 -47px drift），让"末段被吃掉"现象在 paged 模式下消失
- **G2**：保持双页 spread（书脊式左右两页）的现有 UX 和交互（M2.9 引入、M2.5/M2.6 多次打磨）
- **G3**：完全继承现有基础设施——M3.3 precise locator、M3.5 SelectionArea 选区、LXGWNeoXiHei 字体注入、HtmlHighlightInjector 高亮
- **G4**：scroll 模式同步切换到新渲染层（统一架构，避免双轨）
- **G5**：通过机制级不变量测试（TextPainter.height == SelectableText.rich 渲染高度）从源头保证不 drift
- **G6**：Windows 桌面零外部依赖（不引入 WebView2 / inappwebview），保持纯 Flutter

### Non-Goals

- ❌ 不在本轮做 A1（WebView + epub.js）桌面集成（留作长期备选）
- ❌ 不重写 M3.3 Locator 数据模型（charOffset-based 与 TextPainter.getPositionForOffset 同源，无需迁移）
- ❌ 不重写高亮存储 schema（仅在渲染层从 HTML span 改为 InlineSpan decoration）
- ❌ 不评估 PDF 渲染链路（本 spec 只针对 EPUB；PDF 的 pdfium 死结独立线处理）
- ❌ 不在本轮做"翻页动画"等锦上添花（cosmos_epub 自带 page flip，留作 v2）
- ❌ 不支持 EPUB 3 富媒体（video/audio/interactive）—— 智阅当前书库无此场景

## 3. Architecture（新链路 + 关键不变量）

### 3.1 当前死结链路（保留作对照）

```
章节 HTML
  → RenderedHtmlMeasurer（每段独立 HtmlWidget + GlobalKey 读 size）
  → Paginator.paginateFromActualHeights（累加每段高度算 breaks）
  → breaks 喂回 HtmlWidget 渲染每页

问题：单段测量高度 ≠ 整页渲染高度 → drift -47px → 末段被吃
```

### 3.2 新链路（A2）

```
章节 HTML
  → HtmlToInlineSpanConverter（新）转 InlineSpan 树
  → LineMetricsPaginator（新）用整章 TextPainter 行级真实高度切 breaks
  → InlineSpanSubtreeSlicer（新）按 break 切每页 span 子树
  → SelectablePageView（新）每 item = SelectableText.rich(perPageSpan)
  → 双页 spread：Row { SelectableText, SelectableText }
```

**核心不变量（写进测试）**：
> 对任意 InlineSpan S 与任意宽度 W：
> `TextPainter(text: S).layout(maxWidth: W).height` == `SelectableText.rich(S)` 在宽度 W 下 `RenderBox.size.height`

这条不变量成立 ⟺ 测量与渲染同源 ⟺ drift = 0 ⟺ 末段永不被吃。

### 3.3 关键组件

#### 3.3.1 `HtmlToInlineSpanConverter`（新，核心）

**位置**：`reader_engine_epub_view/lib/html_to_inline_span_converter.dart`

**职责**：把章节 HTML 字符串转成 `InlineSpan` 根 + 元数据（每顶级段对应的 plainText offset 范围）。

**输入**：
```dart
String chapterHtml
TextStyle baseStyle
double imageMaxHeight  // 图片 WidgetSpan 的 max-height
double indentEm        // 首行缩进 em 值
bool indentEnabled
```

**输出**：
```dart
class ConvertedSpans {
  final InlineSpan root;          // 整章 span 树
  final String plainText;         // 整章 plain text（与 Locator 坐标系一致）
  final List<SpanRange> ranges;   // 每顶级段对应的 (startOffset, endOffset)
  final List<InlineImage> images; // WidgetSpan 内的图片附件（src/dimensions）
}
```

**支持的 HTML 标签**（覆盖 95% 金融/教材场景）：

| 标签 | 映射 |
|---|---|
| `<p>` | 段落 + 段后间距（自定义 `MarginSpan` 或在 spans 间插空白） |
| `<span>` `<em>` `<i>` | `TextSpan(style: TextStyle(fontStyle: FontStyle.italic))` |
| `<strong>` `<b>` | `TextSpan(style: TextStyle(fontStyle: FontWeight.bold))` |
| `<u>` | `TextSpan(style: TextStyle(decoration: underline))` |
| `<br>` | `TextSpan(text: '\n')` |
| `<h1>`~`<h6>` | `TextSpan` + 加大字号 + 加粗（按 h1=1.5em / h2=1.3em / ... 比例） |
| `<ul>` `<ol>` `<li>` | 每项前缀 `•` 或 `1.` + 缩进 |
| `<a href>` | `TextSpan(style: TextStyle(decoration: underline, color: blue))` + 手势回调 |
| `<img>` | `WidgetSpan(child: Image.network/memory with constraints(maxHeight))` |
| `<blockquote>` | 左侧缩进 + italic |
| `<pre>` `<code>` | `TextSpan(style: TextStyle(fontFamily: monospace))` |
| `<hr>` | `WidgetSpan(child: Divider)` |
| 未识别标签 | **降级**：保留子文本 + WidgetSpan 占位 "⚠️ 复杂元素" |

**降级策略（B1）**：
- 单个未识别标签：转纯文本 + 在原位置插入 `WidgetSpan(Icon + "本段含复杂元素 [SVG/表格/video]，暂不支持")`
- 整章累计 ≥3 个未识别标签：触发章节级降级 → 回退到 fwfh 渲染整章（罕见兜底，记录到日志便于后续扩展）

**首行缩进实现**：
- 原 fwfh 路径：`TypographyStyleInjector.inject` 在 HTML 层注入 EM SPACE 字符
- 新路径：转换器在每个 `<p>` 对应 `TextSpan` 的 **首个子 TextSpan 前插入 `TextSpan(text: indentPrefix)`**
- indentPrefix = `String.fromCharCodes(List.filled(indentEm.truncate(), 0x2003))`（EM SPACE，与现有 injector 同字符）
- 这样 TextPainter 测量时自然包含缩进宽度 → 与最终渲染完全一致

**与 HtmlTextUtils 的关系**：
- 现有 `HtmlTextUtils.htmlToParagraphs` 返回 (plainText, paragraphs) —— 仍保留（用于 Locator 坐标）
- 转换器内部复用 `html_parser` 解析 + `HtmlTextUtils.plainTextOfNode` 提取 plain text
- plainText 字符 offset 坐标与 M3.3 Locator 完全一致（同源算法）

#### 3.3.2 `LineMetricsPaginator`（新）

**位置**：`reader_engine_epub_view/lib/line_metrics_paginator.dart`

**职责**：用整章 `TextPainter.computeLineMetrics()` 的行级真实高度切 page breaks。

**输入**：
```dart
InlineSpan rootSpan
Size viewport
double marginPx
double lineHeight
```

**输出**：`List<PageBreak>`（startOffset/endOffset 基于 plainText 坐标，与现有 paginator.dart 同数据结构）

**算法**：
```dart
final tp = TextPainter(
  text: rootSpan,
  textDirection: TextDirection.ltr,
)..layout(maxWidth: viewport.width - 2 * marginPx);

final lines = tp.computeLineMetrics();
final usableHeight = viewport.height - 2 * marginPx;
final safetyMargin = 0.3 * lineHeight;  // 与现有 paginator.dart 一致

final breaks = <PageBreak>[];
var pageStart = 0;
var pageHeight = 0.0;

for (final line in lines) {
  // 该行在 plainText 中的字符范围
  final startOffset = tp.getPositionForOffset(Offset(0, line.baseline - line.ascent)).offset;
  final endOffset = tp.getPositionForOffset(Offset(line.width, line.baseline + line.descent)).offset;

  if (pageHeight + (line.height) > usableHeight - safetyMargin && pageHeight > 0) {
    breaks.add(PageBreak(startOffset: pageStart, endOffset: startOffset));
    pageStart = startOffset;
    pageHeight = line.height;
  } else {
    pageHeight += line.height;
  }
}
breaks.add(PageBreak(startOffset: pageStart, endOffset: tp.inlineSpan.toPlainText().length));
tp.dispose();
```

**为什么这是行级精度**：
- 旧 `paginator._paginateUncached` 用 TextPainter 估算段级高度（累加段高度，drift 来自段间距/缩进/图片估算偏差）
- 旧 `paginateFromActualHeights` 用 fwfh 实测段级高度（drift 来自 fwfh 单段 vs 整页 layout 差异）
- **新算法直接累加每行高度**，每行的高度就是 `LineMetrics.height`，这是 TextPainter layout 出来的真实值，没有任何估算

**与现有 `paginator.dart:paginateFromActualHeights` 的关系**：
- 函数签名兼容（同样返回 `({String plainText, List<PageBreak> breaks})`）
- 内部实现完全不同
- 调用方（`epubx_renderer._buildPaged`）切换到新方法即可，无需改外部接口

#### 3.3.3 `InlineSpanSubtreeSlicer`（新工具类）

**位置**：`reader_engine_epub_view/lib/inline_span_subtree_slicer.dart`

**职责**：从一个大 InlineSpan 树中切出 `[startOffset, endOffset)` 范围内的子树。

**为什么需要**：
- paged 模式每页要渲染 `plainText.substring(break.start, break.end)` 对应的 span 子树
- 不能简单 `TextSpan(text: substring)`（会丢失所有样式）
- 必须保留原 InlineSpan 的样式（粗体/斜体/链接/图片 WidgetSpan），仅裁剪到字符范围

**算法**：
- 深度优先遍历 InlineSpan 树
- 累积每个叶 TextSpan 的字符长度
- 落在 [start, end) 范围内的 span 保留（裁剪到边界）
- 范围外的 span 跳过
- WidgetSpan：检查其在 plainText 中占的"占位长度"（默认 1 个 U+FFFC OBJECT REPLACEMENT CHARACTER），决定归属哪页

**输出**：一个新的 `InlineSpan`，结构与原 span 一致但仅含目标范围的文本和样式。

#### 3.3.4 `SelectablePageView`（新 widget）

**位置**：`reader_engine_epub_view/lib/selectable_page_view.dart`

**职责**：替代 paged 模式下的 `PageView + HtmlWidget`。

**结构**：
```dart
class SelectablePageView extends StatelessWidget {
  final List<PageBreak> breaks;
  final InlineSpan rootSpan;
  final String plainText;
  final int initialPage;
  final PageController controller;
  final bool dualPageMode;
  final ValueChanged<int>? onPageChanged;
  final SelectionChangedHandler? onSelectionChanged;

  Widget build(...) {
    return PageView.builder(
      controller: controller,
      itemCount: dualPageMode ? (breaks.length / 2).ceil() : breaks.length,
      itemBuilder: (ctx, spreadIdx) {
        if (dualPageMode) {
          final leftIdx = spreadIdx * 2;
          final rightIdx = leftIdx + 1;
          final leftSpan = Slicer.slice(rootSpan, breaks[leftIdx].start, breaks[leftIdx].end);
          final rightSpan = rightIdx < breaks.length
              ? Slicer.slice(rootSpan, breaks[rightIdx].start, breaks[rightIdx].end)
              : null;
          return Row(children: [
            Expanded(child: SelectableText.rich(leftSpan, ...)),
            SizedBox(width: gutterPx),
            Expanded(child: rightSpan == null ? SizedBox() : SelectableText.rich(rightSpan, ...)),
          ]);
        }
        final span = Slicer.slice(rootSpan, breaks[spreadIdx].start, breaks[spreadIdx].end);
        return SelectableText.rich(span, ...);
      },
    );
  }
}
```

**双页 spread**：每个 PageView item 是 Row，含两个 Expanded(SelectableText)，中间 gutterPx 间距。每 spread 占 2 个 break（左页 + 右页），与现有 `_dualPageMode` 逻辑完全兼容。

**SelectionArea 集成**：每个 SelectableText.rich 自带 `onSelectionChanged`，通过 `emitPagedSelection` 推到 `_pagedSelectionController`（M4.6-fix10/A4 已有管道），reader_body 监听 → 与现有 SelectionArea 行为一致。

#### 3.3.5 `_InlineSpanMeasurer`（新 offstage widget）

**位置**：`reader_engine_epub_view/lib/epubx_renderer.dart` 内私有类

**职责**：替代 `RenderedHtmlMeasurer`，在 offstage 用整章 TextPainter 测高（实际上 `LineMetricsPaginator` 内部已经测了，但保留这个 widget 形态是为了与现有 `_buildPaged` 单阶段渲染流程兼容）。

**实现**：本质上就是把 `HtmlToInlineSpanConverter.convert(html)` + `LineMetricsPaginator.paginate(span, ...)` 的结果通过 callback 回传。无需独立 layout。

#### 3.3.6 高亮适配（改造 `html_highlight_injector.dart`）

**现状**：`HtmlHighlightInjector.inject` 在 HTML 层注入 `<span class="zhiyue-highlight" style="background: yellow">...</span>`，然后 fwfh 渲染时显示。

**新路径**：
- 转换器在遍历 HTML 时，遇到 class=`zhiyue-highlight` 的 span，附加 `TextSpan(style: TextStyle(backgroundColor: highlightColor))`
- 高亮颜色映射保持不变（5 色系，M3.2 引入）
- 旧的 HTML 注入路径保留作 fwfh 章节级降级时使用

#### 3.3.7 字体/排版注入（改造 `typography_style_injector.dart`）

**现状**：在 HTML 层注入 EM SPACE 实现首行缩进。

**新路径**：
- 转换器直接在每个段落 TextSpan 的首位插入 `TextSpan(text: indentPrefix)`（同字符 U+2003）
- 字号 / 行高 / 字体族由 `TextStyle` 控制，转换器读取 `TypographyCss.textStyleFromSettings(_typography)` 一次性传给根 TextSpan

## 4. Data Flow（章节切换到翻页的完整链路）

### 4.1 进入章节（cache miss）

```
1. epubx_renderer._currentChapterIndex 更新 → setState
2. build() 拿到 rawHtml = flatChapterHtmlAt(chapterIdx)
3. _buildPaged:
   a. LayoutBuilder 拿到 viewport (rawWidth, rawHeight)
   b. measurementKey = (html, viewport, typography, margin)
   c. cache miss → 同帧挂 offstage _InlineSpanMeasurer
   d. _InlineSpanMeasurer 内部：
      - converter.convert(html) → ConvertedSpans
      - LineMetricsPaginator.paginate(span, viewport, ...) → breaks
      - postFrame callback: _cachedBreaks = breaks; _measurementKey = key
        setState → 触发 rebuild
   e. 同帧用 TextPainter 快速估算 breaks（fallback）渲染 PageView
      （避免空白帧，单阶段 UX，与现有 fix17 同策略）
4. measurer 完成 → setState → rebuild 用真实 breaks
5. SelectablePageView 渲染，用户看到正确分页
```

### 4.2 翻页（cache hit）

```
1. _pageController.nextPage() → PageView 滑到下一页
2. itemBuilder 用 _cachedBreaks 切出该页 span 子树
3. SelectableText.rich(span) 渲染
4. onPageChanged → 更新 currentPage → 进度条更新
5. 章末判定：currentPage == spreadCount - 1 → 弹"读完本章"
```

### 4.3 章节内定位（M3.3 deep link / 书签跳转）

```
1. ScrollToOffsetService 收到 (chapterIndex, charOffset)
2. 二分查找 _cachedBreaks：找到 break.start <= charOffset < break.end 的 breakIdx
3. _dualPageMode ? breakIdx ~/ 2 : breakIdx → spreadIdx
4. _pageController.jumpToPage(spreadIdx)
```

完全复用现有逻辑，只是 break 精度更高。

### 4.4 选区 / 高亮

```
1. 用户长按 SelectableText → 选区起止 offset (本地页面坐标)
2. onSelectionChanged → emitPagedSelection → _pagedSelectionController
3. reader_body 监听 → 转 chapterIndex + 章内 offset（M3.3 同算法）
4. 高亮存储：writeHighlight(chapterIndex, startOffset, endOffset, color)
5. 重渲染：转换器查 chapterHighlights → 在 InlineSpan 树上叠加 BackgroundColorSpan
```

### 4.5 双页 spread（M2.9 兼容）

```
1. LayoutBuilder 检测 rawWidth > 1000（或某阈值）→ setDualPageMode(true)
2. _dualPageMode = true → SelectablePageView itemCount = breaks.length ~/ 2
3. 每 spread = (breaks[i*2], breaks[i*2+1])，左 SelectableText + 右 SelectableText
4. PageController.page 是 spread 索引（与现有逻辑一致）
```

## 5. Architecture Decisions

### AD1：主推 A2（TextPainter 自绘），A1 留作长期备选

**决策**：本轮实施 A2，不动 A1。

**理由**（基于补充调研更新）：

1. **Windows 桌面零外部依赖**（决定性）：
   - A1 需要 `flutter_inappwebview` 6.x Windows 桌面 + WebView2 runtime bundling，所有上层 EPUB 封装（sakura_epub/flutter_epub_viewer/vocsy_epub_viewer）都不支持 Windows
   - 智阅主战场是 Windows 桌面（M7/M8 已交付 Windows 单实例 + Inno Setup 安装器）
   - A2 纯 Flutter，零外部依赖，桌面支持完美

2. **平滑继承现有基础设施**：
   - M3.3 precise locator（charOffset）与 TextPainter.getPositionForOffset 同源
   - M3.5 SelectionArea 选区：SelectableText.rich 原生兼容
   - LXGWNeoXiHei 字体：TextStyle 注入
   - paginator.dart PageBreak 数据结构不变
   - chapter end / tap zone / spread 逻辑全保留

3. **测量与渲染同源 = drift 归零（数学保证）**：
   - TextPainter 测 InlineSpan S 的 height
   - SelectableText.rich(S) 在 RenderParagraph 里也是用 TextPainter layout
   - 两者必然相等（同 paragraph + 同 constraints → 同结果）
   - 这是机制级不变量，可写测试断言

4. **书库场景匹配**：
   - 智阅当前 EPUB 以纯文字金融/教材为主（M3-M4 已交付书库观察）
   - 富 HTML（嵌套表格/SVG/video）是次要场景
   - TextPainter + WidgetSpan 完全够用

5. **A1 的工业级优势在我们当前场景不重要**：
   - A1 强在富 HTML、跨平台一致性、CFI 标准
   - 但智阅当前不需要这些（富 HTML 罕见、跨平台暂只 Windows、Locator 已有自有方案）

**A1 留作长期备选的触发条件**：
- A2 在某些富 HTML 上发现重大覆盖度问题（≥10% 章节降级到 fwfh）
- 或未来需要支持 EPUB 3 富媒体（video/audio/interactive）
- 或未来需要跨平台一致性（iOS/Android/Web）

### AD2：scroll 模式同步切换到新渲染层

**决策**：本 spec 不仅改 paged 模式，也改 scroll 模式，统一到 SelectableText.rich。

**理由**：
- M4.7b 已确认 scroll 模式底层 95% 已实现，但当前用 fwfh 渲染整章
- 改成 SelectableText.rich 后，paged 和 scroll 共享同一渲染层（仅外层 widget 不同：PageView vs SingleChildScrollView）
- 高亮、选区、字体注入的代码只写一次，两模式共用
- scroll 模式天然不会底部溢出（无限高度），但改了之后高亮/选区代码更一致

**风险**：scroll 模式整章一次性 layout，超长章节（> 200KB HTML）可能首次渲染略卡。防御：
- 监控 + 用户感知调查（智阅书库章节普遍 < 50KB）
- 长期若发现问题，改 ListView.builder + 按段懒加载

### AD3：降级策略选 B1（章节统一渲染，复杂标签降级）

**决策**：A2 全章节统一用 SelectableText.rich，少数复杂标签降级到占位 WidgetSpan。

**理由**：
- B1 简单一致，整章一个渲染层
- B2（fwfh + SelectableText 共存）增加复杂度，且 fwfh 仍 drift
- B3（占位不弹原文）用户不可读，UX 差

**降级阈值**：
- 单个未识别标签：自动转纯文本 + WidgetSpan 占位
- 整章累计 ≥3 个未识别标签：触发章节级降级 → 回退到 fwfh 渲染整章（罕见兜底）

### AD4：分阶段交付，可中断

**决策**：分 7 个 phase（详见 plan），每 phase 独立可验证，可中断后无缝续接。

**理由**：
- 总工作量 15-18 天，单次会话不现实
- 每 phase 独立提交，回归测试不回归即可推 main
- 中断后下次直接从断点续（无需理解整个链路）

### AD5：保留 fwfh 依赖不删（仅降级路径用）

**决策**：`flutter_widget_from_html` 依赖保留在 pubspec，仅在章节级降级路径用。

**理由**：
- 兜底路径需要（罕见但重要）
- 完全移除风险大（影响其他可能用到 fwfh 的地方）
- bundle size 增加微小（fwfh 已 tree-shake）

## 6. Risks（风险与防御）

### R1：HTML→TextSpan 转换器覆盖度

- **风险**：用户实际书库的 HTML 标签超出 95% 覆盖度预估
- **影响**：触发章节级降级，部分章节回退 fwfh（仍 drift，但只是少数）
- **防御**：
  - Phase 1 转换器写完后，先跑遍当前书库（M3-M4 已导入的 EPUB）做覆盖率统计
  - 低于 95% 覆盖度则扩展转换器
  - 降级路径保证用户永远有可读内容（即使质量降级）

### R2：WidgetSpan（图片）在 TextPainter 中的测量精度

- **风险**：图片 WidgetSpan 影响 TextPainter.layout 高度，但与最终 RenderParagraph 渲染高度可能不完全一致
- **影响**：图片章节仍可能小 drift
- **防御**：
  - Phase 2 加专门测试：含 WidgetSpan 的 InlineSpan，断言 TextPainter.height == RenderParagraph.size.height
  - spike 验证（半天 timebox）：写最小示例对比
  - 如确有不一致，回退图片到独立 widget（不嵌 WidgetSpan，用 paragraph break 分割）

### R3：性能（整章 TextPainter layout vs fwfh 分段）

- **风险**：整章一次性 TextPainter.layout 比 fwfh 单段慢
- **影响**：进入新章节首次渲染延迟（典型 50KB HTML，预估 50-150ms）
- **防御**：
  - Phase 7 性能验证：随机生成 50KB / 100KB / 200KB 章节，记录 layout 时间
  - < 200ms：用户可接受（与现有 measurer 50-150ms 相当）
  - \> 500ms：改 LineMetricsPaginator 为按段 layout + 拼接（fallback 算法）

### R4：高亮迁移（HTML 注入 → InlineSpan decoration）

- **风险**：现有高亮存储是 (chapterIndex, startOffset, endOffset, color)，渲染时 HTML 注入；新路径改为 InlineSpan decoration，转换器要查表叠加
- **影响**：转换器变复杂，可能性能下降
- **防御**：
  - 转换器接受 `List<Highlight>` 参数，遍历时二分查找落在范围内的 highlight
  - 高亮数量通常很小（每章 < 50 个），二分查找 O(log N) 可忽略

### R5：SelectableText.rich 选区与现有 SelectionArea 行为差异

- **风险**：SelectableText 的 selection 行为可能与现有 SelectionArea（fwfh 提供）有微妙差异（如跨页选择）
- **影响**：用户体验小差异（如选区颜色、handles 样式）
- **防御**：
  - Phase 6 集成测试覆盖 5 个核心选区场景（单击/双击/长按/跨段/跨页）
  - 现有 M4.6-fix10/A4 的 pagedSelection$ 管道复用，仅 widget 层适配

### R6：双页 spread 测量宽度 halve 的精度

- **风险**：双页模式下每页宽度 = (rawWidth - gutter) / 2，TextPainter 测量与实际渲染需用同一宽度
- **影响**：精度误差可能让左右页 break 不齐
- **防御**：
  - LineMetricsPaginator 接受 `measureWidth` 参数（与现有 _buildPaged 同策略）
  - 双页 spread 测试：随机生成章节，断言左页和右页 break 都在行边界

### R7：scroll 模式回归

- **风险**：scroll 模式同步改 SelectableText.rich 后，M3.4 的滚动到位重定位可能失效
- **影响**：scroll 模式书签跳转不准
- **防御**：
  - Phase 4 同步改 scroll 模式 + 滚动重定位（用 TextPainter.getPositionForOffset 反查 pixel offset）
  - 现有 scroll 模式测试不回归

  - `paged_overflow_test`
  - `top_align_test`

  - `chapter_end_test`

  - `M3.3` locator 测试

- **测试**：`dual_page_test` 加新断言"每 spread 含 2 个 break，左页 + 右页 SelectableText.rich 都正确渲染"

- **测试**：Phase 7 性能 baseline

- **验收**：安装包大小不变（< 50MB）；启动时间不增加

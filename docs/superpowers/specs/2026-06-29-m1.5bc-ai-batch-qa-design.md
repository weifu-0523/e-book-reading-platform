## 1. 目标

在 M1.5a 已交付的「单章导读 + 选区点评 + 全书摘要」基础上，补齐两块能力：

1. **批处理**（原 M1.5b）：导入即生成全书章节摘要 + 文本块索引，用户开箱即用，不阻断阅读
2. **同书 Q&A**（原 M1.5c）：基于书内容 FTS5 检索 + LLM 生成带 `[ch=N]` 引用的回答，点击可跳回原文

合并的理由：批处理产出的 `book_passages` chunk 表是 Q&A 的检索源，**共享 chunking 基础设施**让两个能力天然耦合；分两个 spiral 会逼出无谓的接口边界。

**不做**（明确否决）：
- ❌ 成本/token 估算 UI（用户原话："项目是阅读书籍，不分散专注"——见 `feedback_no_cost_estimation` memory）
- ❌ 真正的 merge 冲突解决（既有的 last-write-wins 不动）
- ❌ 跨书 AI 伴读（roadmap phase 3+）
- ❌ 章节摘要缓存失效策略（书更新时整书重新 preprocess；YAGNI 细粒度失效）

- `BookQaService` 与 `AiGuide` 同构（流式 + retry + 错误事件）

## 3. 数据模型（schema v8 → v9）

### 3.1 `book_passages` 表

```sql
CREATE TABLE book_passages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  book_id TEXT NOT NULL,
  chapter_index INTEGER NOT NULL,
  char_offset INTEGER NOT NULL,      -- 在章节文本中的字符起始偏移
  char_length INTEGER NOT NULL,      -- chunk 长度（字符）
  content_text TEXT NOT NULL,
  token_estimate INTEGER NOT NULL,
  created_at INTEGER NOT NULL,       -- drift DateTime → unix seconds
  FOREIGN KEY (book_id) REFERENCES books(id) ON DELETE CASCADE
);

CREATE INDEX idx_book_passages_lookup ON book_passages(book_id, chapter_index);
```

### 3.2 `book_passages_fts` 虚表（FTS5）

```sql
CREATE VIRTUAL TABLE book_passages_fts USING fts5(
  content_text,
  content='book_passages',
  content_rowid='rowid'
);

-- 3 个同步触发器（INSERT / DELETE / UPDATE），仿 annotations_fts
```

**注意**：实际 Q&A 检索**默认走子串 LIKE**，复用 `annotations_dao.dart` 中已验证的 CJK 友好策略；FTS5 表保留作为相关度排序的基础设施，后期可切换。Spec 同时建两者，plan 阶段决定是否启用 FTS5 path。

### 3.3 `qa_history` 表

```sql
CREATE TABLE qa_history (
  id TEXT PRIMARY KEY,               -- uuid
  book_id TEXT NOT NULL,
  question TEXT NOT NULL,
  answer TEXT NOT NULL,
  citations_json TEXT NOT NULL,      -- JSON array of chapter indices, e.g. "[3,5,8]" (parsed via jsonDecode)
  created_at INTEGER NOT NULL,
  FOREIGN KEY (book_id) REFERENCES books(id) ON DELETE CASCADE
);

CREATE INDEX idx_qa_history_book ON qa_history(book_id, created_at DESC);
```

`citations_json` 由 `List<int>.from(jsonDecode(row.citationsJson))` 解析；空数组存 `"[]"`。

### 3.4 schema migration

- `onCreate`：直接建 3 张表 + 索引 + FTS5
- `onUpgrade(from < 9)`：建 3 张新表 + 索引；FTS5 表 fresh，无需 backfill（既有书用户可在 BookDetail 触发手动 preprocess）

### 4.1 BookChunker（M1.5b）

**文件**：`app/lib/services/ai/book_chunker.dart`

```dart
class PassageChunk {
  final int chapterIndex;
  final int charOffset;
  final int charLength;
  final String contentText;
  final int tokenEstimate;
}

class BookChunker {
  static const int _chapterTokenLimit = 100_000;  // 超过则切片
  static const int _sliceTargetTokens = 500;

  /// 切分章节文本。
  /// - 短章（≤100K tokens）：1 chunk
  /// - 长章：按 \n\n 累积到 ~500 token 切片，末段 <100 token 合并
  static List<PassageChunk> chunk(String chapterText, int chapterIndex);
}
```

**纯函数无副作用**，TDD 友好。token 估算复用 `TokenTruncator.estimateTokens`。

### 4.3 BookPreprocessor（M1.5b）

**文件**：`app/lib/services/ai/book_preprocessor.dart`

```dart
sealed class PreprocessEvent {}
class PreprocessProgressEvent extends PreprocessEvent {
  final int currentChapter;
  final int totalChapters;
  final PreprocessPhase phase;  // chunking | summarizing
}
class PreprocessChapterFailedEvent extends PreprocessEvent {
  final int chapterIndex;
  final Object error;
}
class PreprocessDoneEvent extends PreprocessEvent {
  final List<int> failedChapters;
}
class PreprocessErrorEvent extends PreprocessEvent {
  final PreprocessError error;  // terminal errors: authFailed/rateLimited/circuitBroken
}

class BookPreprocessor {
  final BookPassagesDao passagesDao;
  final ChapterTextProvider Function(Book) chapterTextProviderFor;
  final AiGuide aiGuide;  // 复用单章 summarization
  final ApiKeyStoreLike apiKeys;
  final Duration Function() clock;

  Stream<PreprocessEvent> start(Book book);
  void cancel();
}
```

**状态机**：
```
idle ── start() ──> chunking ──> summarizing ──> done
                       │              │
                       └── circuitBroken ──> error
                       └── authFailed   ──> error
                       └── rateLimited  ──> error + 5min cooldown
```

**关键策略**：
- skipIfRunning（同一 bookId 并发 start 只跑一次）
- 2s/章 throttle（防 429）
- 3 章连续失败 → 熔断
- 用户 cancel → 立即停止，已生成数据保留
- resume 时检查 ai_summaries cache，已生成的章跳过

### 4.6 BookQaService（M1.5c）

**文件**：`app/lib/services/ai/book_qa_service.dart`

```dart
sealed class QaEvent {}
class QaChunkEvent extends QaEvent { final String chunk; }
class QaCompleteEvent extends QaEvent {
  final String answer;
  final List<int> citations;  // chapter indices parsed from [ch=N] markers
  final bool fromHistory;
}
class QaErrorEvent extends QaEvent { final QaError error; }

class BookQaService {
  final ApiKeyStoreLike apiKeys;
  final BookPassagesDao passagesDao;
  final QaHistoryDao qaHistoryDao;
  final http.Client? httpClient;

  Stream<QaEvent> ask({required Book book, required String question});
}
```

**流程**：
1. `qaHistoryDao.findSameQuestion(book.id, question)` → 命中则 emit `QaCompleteEvent(fromHistory: true)` 并 return（不重新调 LLM）
2. `apiKeys.load()` → null 抛 noApiKey
3. `passagesDao.searchFts(question, book.id, limit=5)` → topK
4. topK 空 → error(emptyIndex)
5. `PromptBuilder.qa(question, topK)` 拼 context，每个 chunk 前加 `[ch={chapterIndex}]`
6. `OpenAiCompatibleClient.streamChat(prompt)` 流式
7. 完成后 `QaCitationParser.parse(accumulated)` → citations list
8. `qaHistoryDao.insert(...)` 持久化（DB 失败 swallow + log）
9. emit complete

**错误处理**：复用 `AiGuide` 的 retry/exception 分类模式。

## 5. 数据流

### 5.1 M1.5b 导入 → 批处理

```
用户选 EPUB/PDF 文件
  ↓
BookImportService.importFile()
  ├─ 解压 + 写 books 表（既有）
  ├─ 生成首章缩略图（既有）
  └─ 成功后：ref.read(bookPreprocessControllerProvider(book.id)).start(book)
       ↓
       BookPreprocessor.start(book)
       ├─ state = chunking(current=0, total=N)
       ├─ 检查 book_passages 已有？
       │    ├─ 有且 count == 章节数 → 直接进 summarizing 阶段
       │    └─ 否 → deleteForBook + 全量重 chunk
       │
       ├─ Phase 1: Chunking（同步、快速）
       │    for chapter i in 0..N:
       │      text = ChapterTextProvider.get(filePath, i)
       │      if text == null → failedChapters.add(i); continue
       │      chunks = BookChunker.chunk(text, i)
       │      passagesDao.insertMany(book.id, chunks)
       │      emit ProgressEvent(current=i+1, phase=chunking)
       │
       ├─ Phase 2: Summarize（异步、调 LLM）
       │    for chapter i in 0..N:
       │      查 ai_summaries cache (mode='chapter', sourceHash)
       │      命中 → skip
       │      未命中 → ApiKeyStore 检查 → 无 key → break（保留 chunking 成果）
       │              AiGuide.run(chapter, i) → 自动落 ai_summaries
       │      emit ProgressEvent(current=i+1, phase=summarizing)
       │      Future.delayed(2s)
       │      检查 _cancelled → break
       │
       └─ emit DoneEvent(failedChapters)
```

**UI 反馈**：
- `LibraryPage` 书封右上角：`status != idle` 显示 chip "AI 处理中 N/M" 或 "失败 K 章"
- `BookDetailPage` 顶部：`LinearProgressIndicator` + 取消按钮（仅 running 时）
- `ReaderScaffold` chapter drawer：每个已生成摘要的章节旁加 ✓ 标记

### 5.2 M1.5c 提问 → 回答

```
用户在 ReaderScaffold 顶栏点 "问答" icon
  ↓
showDialog → QaAskDialog
  ├─ TextField 输入问题
  ├─ 历史区：qa_history 最近 5 条（点击展开 + 重发）
  └─ 提交按钮
       ↓
       BookQaService.ask(book, question)
       ├─ 检查 qa_history.findSameQuestion → 命中 → emit CompleteEvent(fromHistory=true)
       ├─ 否 → state = loading
       ├─ passagesDao.searchFts(question, book.id, limit=5)
       │    → topK chunks
       ├─ 检查 topK 是否为空
       │    ├─ 空 → emit ErrorEvent(emptyIndex)
       │    │       UI 提示「本书尚未完成预处理」+ 跳转触发 preprocess
       │    └─ 非空 → 继续
       ├─ PromptBuilder.qa(question, topK)
       ├─ OpenAiCompatibleClient.streamChat(prompt)
       │    ├─ chunk → emit ChunkEvent
       │    ├─ complete → 解析 citations + persist + emit CompleteEvent
       │    └─ error → emit ErrorEvent
       │
       └─ state = done(answer, citations=[3, 5])

UI 渲染 QaAnswerView:
  ├─ QaCitationSpanFactory.build(answer, onCitationTap: (ch) {
  │     navigator.pop();  // 关 Q&A dialog
  │     readerScaffoldKey.currentState!.chapterSwitchSettled(ch);
  │   })
  └─ 折叠区 "参考资料"：列出 topK chunks（章节号 + 前 80 字预览）
```

### 5.3 跨流交互

- **预处理未完成时提问**：searchFts 仍可用（已 chunking 的章节），但顶部小字 "预处理进行中，回答可能不全"
- **预处理失败时提问**：searchFts 返回空 → emit emptyIndex → UI 引导重启预处理
- **Q&A 进行中切章节**：dialog 仍浮在最上层，不影响 reader 切换；用户答完点击 [ch=N] 才跳转

## 6. 同步考虑（M2.0x 复用）

`book_passages` 和 `qa_history` 需加入 sync outbox 队列。详细 sync 改动留到 plan 阶段，spec 只标"需 sync"：

- `book_passages`：单本书可能上千行 → 序列化为 `{"type":"book_passages_replace","bookId":"...","chunks":[...]}` 一条记录（整体 replace 语义）
- `qa_history`：单条 sync（与 annotations 同构）
- 这部分**不在本 spiral 实现**，留到 M2.0x（避免范围蔓延）；本 spiral 仅在 sync_outbox 表加一个 type 标记预留位

## 7. 错误处理矩阵

### 7.1 M1.5b（BookPreprocessor）

| 错误 | 检测 | 处理 | UI |
|---|---|---|---|
| 未填 API key | `apiKeys.load() == null` | 跳过 Phase 2（chunking 仍跑完） | 书封无 chip；章节 drawer 提示填 key |
| 401 auth failed | `AiAuthException` | 全停 + state=error(authFailed) | BookDetail 红色 banner "API key 无效，点此修改" |
| 429 rate limited | `AiRateLimitException` | 全停 + 5 分钟 cooldown | Banner "请求过快，5 分钟后自动重试" + 手动重试 |
| 网络 timeout（首章） | `AiNetworkException` | 重试 1 次（2s），仍失败 → 全停 | Banner "网络异常" + 重试按钮 |
| 网络抖动（中段） | 同上，已成功 N 章 | 跳过当前章，记入 failedChapters，继续 | 进度条 "23/45 (2 章失败)" + 重试失败章 |
| EPUB 解析失败 | `ChapterTextProvider.get()` 返回 null | 跳过该章，记入 failedChapters | 同上 |
| 章节 > 100K token | `BookChunker.chunk()` 自动检测 | 切片，正常处理 | 用户无感知 |
| 用户取消 | `_cancelled = true` | 立即停止，已生成保留 | state = idle |
| 应用进后台 | `WidgetsBindingObserver` | 暂停（不取消），resume 继续 | 进度条暂停动画 |
| 重复触发 start | skipIfRunning guard | 直接返回当前 stream | 无 |
| 3 章连续失败 | 计数器 | 熔断 state=error(circuitBroken) | Banner "已熔断，请检查后重试" |

### 7.2 M1.5c（BookQaService）

| 错误 | 检测 | 处理 | UI |
|---|---|---|---|
| 未填 key | `apiKeys.load() == null` | state=error(noApiKey) | Dialog 内提示 + "去设置" 按钮 |
| 索引为空 | `searchFts` 返回空 + count==0 | state=error(emptyIndex) | "本书尚未预处理，点此开始" + 自动触发 preprocess |
| 索引不全 | count < 章节数 | 仍发请求，提示用户 | 顶部小字 "预处理进行中" |
| LLM 网络错 | `AiNetworkException` | retry 3 次（1s/2s/4s） | Dialog "重试中 (2/3)" |
| LLM 返回无 `[ch=N]` | parser 解析空 | 接受回答 + 折叠区为空 | "LLM 未引用具体段落" |
| ch 号越界 | parser 不验证；点击时检测 | 越界 SnackBar "无效章节号" | 用户感知 |
| 重复提问 | `findSameQuestion` 命中 | 直接显示历史（不重调 LLM） | 历史区高亮 |
| persist qa_history 失败 | DB exception | swallow + log；答案仍显示 | 用户无感知 |

### 7.3 共用：超时策略

- LLM stream 单 chunk 间隔 > 30s 视为 stalled → 抛 timeout
- 总响应 > 90s 取消（用户可点 "停止"）
- FTS5 query < 1s 应完成；否则 db 锁，retry 1 次

## 12. 风险清单

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| R1 | 批处理调用 LLM 量级大（30 章 × 0.002 = 0.06 元/书），用户没预期 | LOW | 用户主动决定是否填 key；未填 key 时 chunking 仍跑（Q&A 仍可用） |
| R2 | book_passages 表膨胀（厚书 + 长章切片 → 上万行） | MEDIUM | 按 chapterIndex 索引；UI 只读 limit K；FTS5 外部 content 表不重复存储 |
| R3 | LLM 回答不遵守 `[ch=N]` 格式 | MEDIUM | Prompt 强约束 + parser 容错；折叠区兜底显示原 chunks |
| R4 | preprocess 中途 app crash，状态不一致 | MEDIUM | start 时检测既有 chunks 数 + ai_summaries cache 命中 → 续跑而非重跑 |
| R5 | 网络抖动期间 3 章熔断频繁触发 | MEDIUM | cooldown 5 分钟（同 M2.0b）+ 手动重试入口 |
| R6 | FTS5 unicode61 对 CJK 检索效果差 | LOW | 默认走 LIKE 子串匹配（复用 annotations_dao 已验证策略） |
| R7 | chapterSwitchSettled 跳转后用户找不到位置（章节长） | LOW | 折叠区点击「跳转 + 滚动到首段引用」；后续 spiral 加深链 |
| R8 | 测试用真 LLM 不可行 | LOW | mock OpenAiCompatibleClient（已有模式） |

| 问题 | 决策方向 |
|---|---|
| book_passages 是否真启用 FTS5 检索 path | 倾向默认 LIKE，FTS5 表建好备用 |

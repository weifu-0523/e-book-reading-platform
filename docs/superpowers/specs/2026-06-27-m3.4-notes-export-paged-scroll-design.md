### 2.1 模块边界（单一职责）

- **MarkdownExporter**：纯 Dart 函数。输入 `BookNote + Book`，输出 `String`。零副作用、零 Flutter 依赖、零文件系统依赖。可独立单测（golden file 对比）。
- **NoteFileWriter**：静态方法。输入 `String content + String suggestedName`，输出 `Future<String?>`（写入路径，取消返回 null）。封装 `file_picker` + `dart:io.File`。不依赖 BookNote 模型。
- **NotesPage**：UI 层。从 repository 拿 BookNote，渲染列表，编排导出。不写 Markdown 也不写文件。
- **ScrollToOffsetService**：保持现有 scroll 模式算法；新增 paged 模式分支（breaks → jumpToPage → in-page offset → 复用核心算法）。

## 4. Markdown 导出

### 4.1 格式规范（Obsidian 兼容）

```markdown
---
title: "书名"
author: "作者"
source: "EPUB"
exported_at: 2026-06-27T14:32:00
total_highlights: 12
total_notes: 5
reading_started: 2026-03-01
reading_ended: 2026-06-27
tags: [心理学, 认知科学]
---

# 《书名》读书笔记

> 阅读时间：2026-03-01 ~ 2026-06-27
> 共 12 条高亮 · 5 条笔记

## 核心摘要

（summary 内容）

## 核心知识点

- 知识点 1
- 知识点 2

## 高亮与笔记

### 第一章 · 章节名

> 🟡 原文引用内容...
- 💬 我的笔记：xxxx
- 🏷️ #标签1 #标签2

### 第二章 · 章节名
> 🔴 原文引用内容...

---

## 标签

#心理学 #认知科学
```

### 4.2 格式决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | frontmatter 全 YAML | Obsidian 索引必备；日期 ISO 8601 机器可读 |
| 2 | 颜色 emoji 前缀：🟡yellow 🟢green 🔵blue 🔴red 🟣purple | design doc §4.3 指定；跨平台可见 |
| 3 | 章节标题从 `EpubRangeLocator.chapterTitle` 读 | M3.3 决策 #5 已写入 locator；缺则 `第 N 章` |
| 4 | summary/keyTakeaways/tags 为空时整段省略 | YAGNI；不留空 heading |
| 5 | 不带行号/页码 | EPUB 无稳定页码；CFI 不友好；元数据行（CFI/时间）默认隐藏 |
| 6 | 标签用 `#tag` 而非 `[[tag]]` | Obsidian 两种都识别；`#` 兼容 Bear/Logseq |
| 7 | 空 annotations 仍导出 | body 只有 `## 高亮与笔记\n\n（暂无高亮）` |
| 8 | annotations 按 chapterIndex 升序，同章内按 createdAt 升序 | 阅读顺序 |

### 5.2 ScrollToOffsetService 扩展

```dart
// app/lib/features/reader/services/scroll_to_offset.dart
static Future<void> scrollToCharacterOffset({
  required BuildContext context,
  required ScrollableState scrollable,
  required int targetOffset,
  required PaginationMode paginationMode,  // ← 替换 isPagedMode: bool
  List<PageBreak> pageBreaks = const [],   // ← paged 模式必传
  PageController? pageController,          // ← paged 模式必传
  Duration duration = const Duration(milliseconds: 300),
}) async {
  if (paginationMode == PaginationMode.scroll) {
    return _scrollToOffsetInScrollView(
      scrollable: scrollable,
      targetOffset: targetOffset,
      duration: duration,
    );
  }
  // paged 模式
  if (pageController == null) {
    assert(false, 'pageController required in paged mode');
    return;
  }
  if (pageBreaks.isEmpty) return;
  
  // 1. 找目标页
  int pageIdx = _findPageForOffset(pageBreaks, targetOffset);
  
  // 2. 跳页（无动画）
  pageController.jumpToPage(pageIdx);
  
  // 3. 等当前页 mount + layout
  await WidgetsBinding.instance.endOfFrame;
  
  // 4. 算 in-page offset 并复用核心算法
  final inPageStart = pageBreaks[pageIdx].startOffset;
  await _scrollToOffsetInScrollView(
    scrollable: scrollable,
    targetOffset: targetOffset,
    duration: duration,
    cumulativeBase: inPageStart,  // ← 重构：核心算法接受 base 偏移
  );
}

static int _findPageForOffset(List<PageBreak> breaks, int offset) {
  for (var i = 0; i < breaks.length; i++) {
    if (breaks[i].endOffset > offset) return i;
  }
  return breaks.length - 1;  // 越界 → 末页
}
```

**核心算法重构**：

```dart
// 既有 scroll 模式算法，重构为接受 cumulativeBase
static Future<void> _scrollToOffsetInScrollView({
  required ScrollableState scrollable,
  required int targetOffset,
  required Duration duration,
  int cumulativeBase = 0,  // ← 新增。scroll 模式 0；paged 模式 pageBreak.startOffset
}) async {
  // 算法主体：DFS 收集 RenderParagraph → 累积字符长度找 owner → getOffsetForCaret → animateTo
  // 唯一变化：找 owner 时，cumulative 从 cumulativeBase 起算（不是 0）
  // 实际上 owner 匹配条件变为：(cumulative + len > targetOffset) 但 cumulative 从 base 起累
}
```

**为何 cumulativeBase 不让算法本身改写**：scroll 模式 cumulative 从 0 起，遍历所有 RenderParagraph；paged 模式只 mount 当前页，遍历的就是当前页的 RenderParagraph，cumulative 从 pageBreak.startOffset 起，遍历到 pageBreak.endOffset 止。算法本体不变，只是初始值不同。

### 5.4 边界条件

| 场景 | 处理 |
|---|---|
| scroll 模式 | 走既有分支，pageBreaks/pageController 忽略 |
| paged 模式但 pageController null | assert（开发期 bug）；release build silent return |
| paged 模式但 pageBreaks 空 | silent return（章节首次未渲染） |
| targetOffset 越界 | `_findPageForOffset` fallback 末页，in-page 滚到底 |
| jumpToPage 后页面未及时 mount | endOfFrame 等一帧；若仍空 silent return |

### 5.5 兑现 M3.3 spec R2

M3.3 spec R2 原文：

> **`ScrollToOffsetService` 只在 `PaginationMode.scroll` 下正确**。生产默认 `PaginationMode.paged`... **M3.4 必须实现 paged 精确滚动**（需 engine 暴露 Paginator breaks → jumpToPage → in-page offset）。

本节 5.1-5.4 完整实现该承诺。M3.3 留下的另两项限制（图片 alt 精度、多匹配 anchor）仍属 M3.4+，不在本 sprint。

## 9. 决策记录

### R1: 章节标题从 locator 读，不开新 engine 实例

**决策**：NotesPage 直接读 `EpubRangeLocator.chapterTitle`，不为解析 toc 开 engine 实例。

**理由**：M3.3 决策 #5 已让创建高亮时把 chapterTitle 写入 locator。开新 engine 实例（仅为 toc）成本远高于直接读已有字段，且 engine 实例化需要打开 EPUB 文件，对 NotesPage 这种轻量浏览过重。

**影响**：M3.3 之前的高亮（无 chapterTitle）会显示 `第 N 章` fallback。M3.3 之后的高亮（已写入 chapterTitle）显示真实章节名。可接受——M3.3 之前的高亮用户可手动重新触发 locator resolve。

### R2: 文件名后缀 ` - 读书笔记.md` 而非仅 `.md`

**决策**：`《思考快与慢》 - 读书笔记.md` 而非 `《思考快与慢》.md`。

**理由**：用户可能把多本书的笔记导出到同一目录（如 Obsidian vault）。书名相同后缀 `.md` 易与原书文件混淆；加 ` - 读书笔记` 后缀让用途一目了然，且 Obsidian 友好（识别为 note 而非 source）。

### R3: 不实现 Android SAF（M3.4），仅 Windows

**决策**：M3.4 优先 Windows 路径；Android 路径实现到 `file_picker.getDirectoryPath` 调用层即可，但持久化授权/媒体库扫描等细节推后。

**理由**：单人项目，桌面端是主要工作环境（spec 主线）。Android 用 `share_sheet` 分享单文件可能比目录选择更自然，需独立设计——不在本 sprint。M3.4 先交付桌面导出闭环。

### R4: 元数据行（CFI/时间）默认隐藏

**决策**：每条 annotation 不显示 CFI 和精确时间。仅在 frontmatter 记录 reading_started/ended。

**理由**：CFI 对人不可读；精确时间戳让 .md 文件嘈杂；阅读者关心"内容+章节"，不关心"何时高亮的"。需要元数据时 Obsidian 自己渲染 createdAt/updatedAt 也容易（M3.5 可能加 toggle）。

### R5: 重构 PageBreak 到 reader_engine 而非继承

**决策**：`PageBreak` 类直接从 `reader_engine_epub_view` 移到 `reader_engine/lib/core/`，paginator.dart import 共享类型。

**理由**：PageBreak 是不可变值对象，无 platform-specific 行为。共享类型避免重复定义 + 引入新抽象层（如 mixin/接口）的成本。`paginator.dart` 内既有 `PageBreak` 字段（startOffset/endOffset）不变，只是 import 改了。

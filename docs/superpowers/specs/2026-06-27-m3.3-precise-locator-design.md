## 1. 定位与约束

### 1.1 在整体路线图中的位置

M3 = MVP 1.0 全功能收官 sprint。M3.2 已交付高亮/笔记/跨书搜索，但在 spec 4.3 节明确记录："本 sprint 走简化方案（文本搜索定位）。若用户实测发现定位漂移，M3.3 升级为 offset-based"。

M3.2 落地后暴露三个 follow-up（均已在代码 doc comment 标注）：

1. `_resolveLocator` 用 `0..text.length` 占位 → 高亮 offset 失真
2. `NotesDrawer.chapterTitles` 暂留空 map → drawer 无章节标题
3. `SearchHighlightsPage.AnnotationTile` 无 `onTap` → 搜索结果不能回跳原书

**M3.3 重新定义**：原 M3.2 spec 路线图把 "per-book 笔记视图 + Markdown 导出" 列为 M3.3。基于 M3.2 落地后的实际状态与用户决策，M3.3 改为 "精确 locator 收尾 sprint"。原 per-book 笔记视图推迟到 M3.4，Markdown 导出推迟到 M3.5。MVP 1.0 总工期顺延约 0.5 周。

### 1.2 M3.3 范围

**目标**：让 M3.2 的"长按高亮 → drawer 浏览 → 搜索回跳"链路从"能跑"升级到"精准"。所有高亮携带真实字符 offset + 章节标题；drawer 显示章节名；搜索结果 tap 后跳到原书原位置。

**包含**：

- `reader_engine` 新增 `currentChapterPlainText` API：解析当前 spine item DOM，拼接 text nodes，per chapter 缓存
- `resolveSelectionLocator` 改用真实 `text.indexOf(selection)` 计算 `startOffset` / `endOffset`
- `toc_title_resolver` 服务：把 `TocEntry` 树 flatten 成 `{chapterIndex: title}` map
- `NotesDrawer` 接入 `chapterTitles` map，按真实章节标题分组显示
- 创建高亮时把 `chapterTitle` 写入 `EpubRangeLocator.chapterTitle` 字段
- `scroll_to_offset` 服务：walk `RenderObject` 树，定位含 offset 的 `RenderParagraph`，`getOffsetForCaret` + `getTransformTo` 算 scrollable 内坐标，`animateTo` 滚动
- `SearchHighlightsPage.AnnotationTile` 接 `onTap`：`context.push('/book/$bookId', extra: locator)`
- `ReaderPage` 新增 `initialLocator` 参数：路由 `extra` 注入，engine ready 后 `gotoLocator` + `scrollToCharacterOffset`
- `_onAnnotationTap` 扩展：`gotoLocator` 后追加 `scrollToCharacterOffset`

**不包含**（明确推迟）：

- per-book 笔记视图 Tab + Markdown 导出（M3.4）
- 知识库 KnowledgeEntry（M3.5）
- 选区多匹配 disambiguation 升级（如同短语二次匹配用相邻文本 anchor）— M3.3 取首匹配
- 非文本节点（图片 alt 等）精确定位 — M3.3 接受略偏
- 跨设备同步（MVP 2.0）

### 1.3 依赖与前置条件

- **M3.2 已就绪**：tag `m3.2-complete` at `156806b`；285 app tests + 25 reader_engine + 56 reader_engine_epub_view = 366 全绿
- **`EpubRangeLocator`** 字段已含 `chapterIndex` / `chapterTitle?` / `startOffset` / `endOffset` / `quote`（M3.2 已建）
- **`reader_engine` 现有 API**：`gotoLocator(Locator)` / `gotoTocEntry(TocEntry)` / `nextSpine` / `previousSpine` / `Stream<Locator> currentLocation$` / `TableOfContents? toc`
- **`TableOfContents`** 结构：`List<TocEntry>`，每 `TocEntry` 含 `title` / `locator` / `children`，locator 可为 `EpubCfiLocator`（含 `chapterIndex`）
- **`SelectableRegion`** 已在 `ReaderPage` 外层包裹（M3.2 T20 落地，解决手势冲突）
- **当前 `_onSelectionChanged`** 拿到 `SelectedContent.plainText`，但未与章节 plainText 对齐

### 1.4 已知风险

- **R1**：`reader_engine` 现有 spine DOM 解析能力未知。`EpubxRenderer` 内部用 `HtmlWidget` 直接渲染，未必保留 DOM 树访问入口。**Mitigation**：T1 先 spike——查 `EpubxRenderer` 是否有 `currentSpineHtml` 或类似 API；若无可直接用 HTML 字符串走 `html_parser` 提取 text nodes，与渲染同源。
- **R2 (confirmed limitation)**：`ScrollToOffsetService` 算法只在 `PaginationMode.scroll` 下正确。`PaginationMode.paged`（生产默认）下 `PageView` 只挂载当前页 RenderParagraphs，跨页 offset 计算无解。M3.3 实现走 `isPagedMode` 短路（仅 gotoLocator 跳章节），M3.4 接入 Paginator breaks 实现 paged 精确滚动。
- **R3**：`getOffsetForCaret` 对 `TextPosition.affinity` 边界情况返回值可能抖动。**Mitigation**：使用 `Rect.zero` 作为 caret metrics，取 `.down` 方向最大值稳定。
- **R4**：deep-link 路径上 `engine.ready` 与 `gotoLocator` 之间存在竞态。`readerEngineForBookProvider` 是 `FutureProvider`，`ReaderPage.build` 用 `.when`。**Mitigation**：`initialLocator` 在 `.when(data:)` 分支内 engine 首次 ready 后调用，用 `_initialLocatorHandled` flag 防重入。
- **R5**：`scrollToCharacterOffset` 在 chapter 刚切换、RenderObject 树尚未 layout 时调用会找不到 `RenderParagraph`。**Mitigation**：调用方先 `await engine.gotoLocator(...)`，再 `await WidgetsBinding.instance.endOfFrame`（等一帧 layout），最后 `scrollToCharacterOffset`。

## 3. 数据/API 设计

### 3.1 `ReaderEngine.currentChapterPlainText`

```dart
abstract class ReaderEngine implements Disposable {
  // ... 现有 ...

  /// 当前 spine item 的纯文本（已展开实体、剥除标签、不含 alt 等）。
  ///
  /// 实现层：解析当前 chapter HTML → walk DOM text nodes → 拼接。
  /// 同 chapterIndex 重复调用走缓存（keyed by chapterIndex + html hash）。
  /// 失败（HTML 解析异常）抛 [StateError]，由调用方降级（fallback 用 quote 子串）。
  Future<String> get currentChapterPlainText;
}
```

**实现要点**：

- `EpubxRenderer` 内部已持有当前 chapter HTML 字符串（`chapters[_currentChapterIndex].htmlContent`）
- 复用 `package:html` 的 `HtmlParser` 解析为 `html.Document`，walk `document.querySelectorAll('*')` 累积 `node.text`
- 缓存：`final Map<int, String> _plainTextCache = {};`，key 是 chapterIndex
- 切换 chapter（`_currentChapterIndex` 变更）不主动清缓存——按 chapterIndex lazy lookup 即可

**边界**：

- `<br/>` 不贡献字符（保持）
- `&amp;` → `&`（`html` 包自动解码）
- `<script>` / `<style>` 内容不贡献（用 `node.querySelector` 排除）
- 嵌套 `<p><b>x</b>y</p>` → `"xy"`（DOM walk 自然顺序）

### 3.2 `TocTitleResolver`

```dart
class TocTitleResolver {
  /// Flatten `TableOfContents` 为 `{chapterIndex: title}` map。
  ///
  /// Walk 算法：深度优先遍历，每访问一个 [TocEntry]：
  /// - 若 `entry.locator is EpubCfiLocator`，取 `chapterIndex` 作 key
  /// - 若 `entry.locator` 是其他类型，跳过（不贡献 chapter 标题）
  /// - 重复 chapterIndex：先到者优先（depth-first 自然序保证目录先后）
  static Map<int, String> resolve(TableOfContents? toc);
}
```

**为什么 depth-first**：EPUB toc.ncx 通常按 spine 顺序排列，深度优先遍历得到的 chapterIndex → title 映射与用户阅读顺序一致。BFS 会让子章节先于父章节命中。

### 3.3 `ScrollToOffsetService`

```dart
class ScrollToOffsetService {
  /// Walk `scrollable.context.findRenderObject()` 下所有 `RenderParagraph`，
  /// 累积字符位置找到拥有 `targetOffset` 的 paragraph，滚到该位置。
  ///
  /// 流程：
  /// 1. 收集 RenderParagraph（按 document order = widget tree DFS）
  /// 2. 累积 `paragraph.text.toPlainText().length`，找 owner
  /// 3. `getOffsetForCaret(TextPosition(offset: localOffset), Rect.zero)` 得 caret local
  /// 4. `owner.getTransformTo(scrollable.findRenderObject())` 得 transform
  /// 5. `MatrixUtils.transformPoint(transform, caretLocal)` 得 scrollable-local (x, y)
  /// 6. `scrollable.position.animateTo(y, duration: 300ms, curve: easeInOut)`
  ///
  /// 找不到 owner（offset 超出 plainText 范围）：silent return（log warning）。
  static Future<void> scrollToCharacterOffset({
    required BuildContext context,
    required ScrollableState scrollable,
    required int targetOffset,
  });
}
```

**为什么用 `getTransformTo` 而非 `localToGlobal`**：

- `localToGlobal` 返回屏幕坐标，含当前 scroll 偏移；要还原 content 坐标需手动加回 `scrollable.position.pixels`，多一步易错
- `getTransformTo(target)` 直接给 paragraph → scrollable 的 4x4 matrix，含所有祖先 transform（含 scroll offset = 0 时的 layout 位置），`MatrixUtils.transformPoint` 应用得 content 坐标

**单次调用 vs 多 paragraph 边界**：

- 选区跨越多个 paragraph（如 `<p>abc</p><p>def</p>` 选 "cde"）时，`targetOffset = startOffset` 落在第一个 paragraph，caret 定位精准
- 算法不在乎是否跨 paragraph，只算 start

### 3.4 `resolveSelectionLocator` 改写

```dart
Future<EpubRangeLocator?> resolveSelectionLocator({
  required String selectedText,
  required int chapterIndex,
  required String chapterPlainText,
  String? chapterTitle,
}) async {
  if (selectedText.isEmpty) return null;
  final startOffset = chapterPlainText.indexOf(selectedText);
  if (startOffset < 0) {
    // 选中文本不在当前章节 plainText 中（理论上不应发生，因 selection 来自该章节渲染）
    // 降级：不持久化高亮，由调用方弹 snackbar
    return null;
  }
  return EpubRangeLocator(
    chapterIndex: chapterIndex,
    chapterTitle: chapterTitle,
    startOffset: startOffset,
    endOffset: startOffset + selectedText.length,
    quote: selectedText,
  );
}
```

**为什么从同步改为 async**：原 `resolveSelectionLocator(text, chapterIdx)` 同步。新签名要拿 `chapterPlainText`，而 plainText 来自 engine 异步 API。包装成 async 让调用方 `await`，避免 caller 各自 `await engine.currentChapterPlainText` 重复代码。

**多匹配处理**：`indexOf` 返回首个命中。同短语在本章内多次出现时，高亮会落在第一个位置——记入 R4 已知限制，M3.4 升级（用相邻文本 anchor disambiguate）。

### 3.5 `ReaderPage` 扩展

```dart
class ReaderPage extends ConsumerStatefulWidget {
  final String bookId;
  final Locator? initialLocator;  // 新增，来自路由 extra

  const ReaderPage({super.key, required this.bookId, this.initialLocator});

  @override
  ConsumerState<ReaderPage> createState() => _ReaderPageState();
}
```

`_ReaderBodyState` 新增：

```dart
bool _initialLocatorHandled = false;

@override
void didChangeDependencies() {
  super.didChangeDependencies();
  _maybeHandleInitialLocator();
}

Future<void> _maybeHandleInitialLocator() async {
  final loc = widget.initialLocator; // 通过 _ReaderBody 构造传入
  if (loc == null || _initialLocatorHandled) return;
  _initialLocatorHandled = true;
  await engine.gotoLocator(loc);
  await WidgetsBinding.instance.endOfFrame; // 等 layout
  if (!mounted) return;
  final scrollable = Scrollable.of(context);
  if (scrollable == null) return;
  if (loc is EpubRangeLocator) {
    await ScrollToOffsetService.scrollToCharacterOffset(
      context: context,
      scrollable: scrollable,
      targetOffset: loc.startOffset,
    );
  }
}
```

`_onAnnotationTap` 同样扩展（gotoLocator 后追加 scrollToOffset）。

## 4. 错误处理

| 场景 | 处理 |
|---|---|
| `currentChapterPlainText` 失败（HTML 解析异常） | 抛 StateError；`_onToolbarHighlight` catch → snackbar "无法定位选区，请重试"；不持久化 |
| `indexOf` 返回 -1（选区不在 plainText） | `resolveSelectionLocator` 返回 null；上层 snackbar；记 warning log |
| `TocTitleResolver` 输入 null | 返回 `{}`（与现有 NotesDrawer chapterTitles 默认值兼容） |
| `ScrollToOffsetService` 找不到 owner paragraph | silent return + log warning；用户看到章节顶部（gotoLocator 已切章节） |
| `RenderObject` 树未 layout（章节刚切） | 调用方 `await endOfFrame`；若仍 layout 未完成，下一帧重试一次（用 `WidgetsBinding.instance.addPostFrameCallback`） |
| `initialLocator` 与当前书 chapterIndex 不一致 | engine.gotoLocator 内部处理（按 locator.chapterIndex 切 spine） |
| 重入 `_maybeHandleInitialLocator`（build 多次） | `_initialLocatorHandled` flag 保证只跑一次 |

## 8. 决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 偏移实现层 | A：engine 暴露 `currentChapterPlainText`，app 算 offset | 单一数据源；engine 端可独立单测；与渲染同源（都来自 HTML 字符串）保证一致性 |
| 滚动实现层 | app 层 `ScrollToOffsetService` | 需要 BuildContext + RenderObject 树；engine 不应感知 Flutter widget 层 |
| 滚动坐标转换 | `getTransformTo` 而非 `localToGlobal + pixels` | 直接得 content 坐标；少一步算术，少一处易错 |
| 多匹配策略 | 首匹配（indexOf） | 简单可预测；用户面 99% 场景；disambiguate 用 anchor 留 M3.4 |
| `chapterTitle` 写入 locator | 创建时填，不依赖 drawer 查表 | locator 自包含，跨页面/跨设备稳定 |
| `initialLocator` 入口 | 路由 `extra` 而非 query param | locator 含特殊字符（quote）；query param 需 encode；extra 直传对象 |
| `_initialLocatorHandled` flag | 在 `_ReaderBodyState.didChangeDependencies` 触发 | engine ready 后第一帧即可调；flag 防多 build 重入 |
| `scrollToOffset` 失败策略 | silent return + log | gotoLocator 已保证章节正确；scroll 仅是 UX 优化，失败不阻塞 |
| M3.3 范围 vs 原 spec | 三项 M3.2 follow-up 全做 + 滚动；原 per-book 笔记视图推 M3.4 | 用户实测定位漂移会影响 MVP 1.0 体验；优先收尾再扩展 |
| `currentChapterPlainText` 缓存 key | chapterIndex（单 book session） | 切 book 重置（_ReaderBody 重建）；同一 chapter HTML 不变则 plainText 不变 |

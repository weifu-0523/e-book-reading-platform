## 1. Context(为什么做)

用户要求新增 `.md` / `.txt` 书籍格式支持。当前平台仅支持 EPUB(`EpubxRenderer` + epubx + flutter_widget_from_html)与 PDF(`PdfRenderer` + pdfrx)。

三个并行 Explore agent 已完整摸清现有架构,得出三条决定性结论:

1. **EPUB 渲染管道是格式无关的**。`EpubxRenderer` 的整套链路:
   - `Paginator`(TextPainter 测量分页)→ `HtmlSlicer`(按 plain 范围裁 HTML)→ `TypographyStyleInjector`(段落首行缩进 em-space)→ `HtmlHighlightInjector`(高亮 `<span>`)→ `_PageVerticalAligner`/`_DualSpreadAligner`(版心对齐)→ `HtmlWidget`(fwfh 渲染)
   - 只要喂入"章节 HTML 字符串"就能工作。MD(`markdown` 包 `markdownToHtml()`)与 TXT(按空行分段包 `<p>`)都能转成 HTML,**无需重写任何渲染/分页/高亮/双页逻辑**。

2. **`reader_body.dart` 有 12 处 `engine is ConcreteEpubReaderEngine` 检查**,gate 着双页模式(`dualPageMode` getter/setter)、高亮注入(`injectHighlights`)、章节末提示(`chapterEndEvents`)、章节摘录(`rendererRef`)、TOC 跳转等全部 EPUB 能力。这些能力本质都是 **HTML 分页渲染层**的能力,不是 epubx 特有的。MD/TXT 只要复用同一渲染栈,就能零改 UI 继承全部能力。

3. **存在 5 处"三元地雷"**:对未知格式默认降级成 PDF —— 不显式分支会让 MD/TXT 被误当 PDF 而崩溃:
   - `app/lib/data/models/book.dart:83`(`fromRow` ternary)
   - `app/lib/services/book_import_service.dart:66-67`(extension ternary)
   - `app/lib/features/reader/providers/reader_engine_provider.dart:47,53`(format 映射 + 引擎路由)
   - `app/lib/features/notes/services/markdown_exporter.dart:259-265`(导出标签)
   - `app/lib/core/app_providers.dart` AI provider 分支 + `book_text_extractor.dart:117`

DB 无需迁移:`books.format` 列是纯 TEXT,无 CHECK 约束,`schemaVersion` 保持 10。

## 2. Goals

- 能导入/打开/阅读 `.md` 与 `.txt` 文件,行为与 EPUB 一致(分页翻页、字号/主题/双页切换、高亮摘录、阅读进度记忆)
- MD 按 `#`/`##` 标题切章(无标题则单章);TXT 整篇单章
- MD/TXT 支持 AI 伴读/总结/章节摘录(加 chapterTextProvider + textExtractor 分支)
- 目录 tab 有内容(MD 显示标题树;TXT 显示单条"全文")
- 复用 EPUB 全部渲染能力,不重写分页/高亮/双页

## 3. Non-Goals(本期不做)

- **MD 原生 markdown 渲染器**(`flutter_markdown`):走 md→html→fwfh,保持与 EPUB 一致的渲染与高亮语义。fwfh 对标准 HTML 的支持已足够覆盖 MD 常见元素(标题/列表/代码块/引用/链接/粗斜体)。
- **TXT 按字数自动切章**:本期 TXT 单章(用户已确认)。长 TXT 靠分页翻页阅读,目录显示单条。
- **封面提取**:MD/TXT 无封面,沿用现有首字母占位图(`BookCover._Placeholder`,按标题首字符 + hash 配色)。
- **Android MethodChannel mimeType 扩展**:本期聚焦 Windows 桌面 + 文件选择器导入。Android 的 `text/markdown`、`text/plain` mimeType + `.md`/`.txt` pathPatterns 留 follow-up。
- **TXT 编码自动探测的复杂实现**:默认 UTF-8,解码失败降级 latin1(保证不乱码、不崩溃)。不做 GBK/Big5 等多编码启发式探测。

## 4. 架构决策

### A1 — 抽出格式无关的 HTML 分页渲染引擎(核心决策)

**问题**:`EpubxRenderer`(1211 行)把两个职责耦合在一个类里:
- (a) **epubx 解析**:`openFile` → `EpubReader.readBook(bytes)` → `EpubBook` / `EpubChapter` 树(`epubx_renderer.dart:445-470`)
- (b) **HTML 渲染**:`build`/`_buildPaged`/`_buildScroll`/分页/高亮/双页(`epubx_renderer.dart:848+`)

MD/TXT 要复用 (b) 但完全不需要 (a)。

**决策**:在 `reader_engine_epub_view` 包内(不新建独立包)引入抽象层:

- **`HtmlChapterSource`**(@immutable 数据类,`{title, html}`):格式无关的章节抽象,对应 EPUB 的 `EpubChapter` 但去除 epubx 依赖。
- **`HtmlChapterReaderEngine implements ReaderEngine`**:格式无关的渲染引擎。接收 `List<HtmlChapterSource>`,内部用与 `EpubxRenderer` **完全相同**的 Paginator/HtmlSlicer/injector/HtmlWidget 渲染。提供 EPUB 全部渲染层能力:`dualPageMode`、`setDualPageMode`、`injectHighlights`、`chapterEndEvents`、`rendererRef`。
- **`ConcreteEpubReaderEngine` 重构**:保留类名(降低改名波及,`reader_body.dart` 12 处 cast 不用动),内部委托给 `HtmlChapterReaderEngine`。自己只保留"EPUB 文件 → `List<HtmlChapterSource>`"的加载职责。**对外暴露的 EPUB 特有方法(`chapterEndEvents`/`rendererRef`/`setDualPageMode`/`injectHighlights`/`dualPageMode`)全部转发到内部的 `HtmlChapterReaderEngine`**。
- **`EpubxRenderer` 拆分**:`openFile` 仍用 epubx 解析,产出 `List<HtmlChapterSource>`;渲染相关方法委托。

**为何不新建独立包(如 `reader_engine_md_view`)**:MD/TXT 与 EPUB 共享同一套 fwfh 渲染栈(Paginator/HtmlSlicer/injector/_PageVerticalAligner 等),这些工具目前都在 `reader_engine_epub_view` 包内且未导出。新建独立包要么(a)把这些工具搬移到 `reader_engine` 共享包(大改动,跨包移动 + 改 EPUB import),要么(b)在 MD 包里重复实现(违反 DRY)。**留在 `reader_engine_epub_view` 包内、新增抽象层,改动面最小、零跨包搬移**。包名 `reader_engine_epub_view` 略显不妥(以后承载 MD/TXT),可在后续里程碑重命名为 `reader_engine_html_view`(本期不动,避免波及 pubspec path 依赖)。

**复用度**:Paginator/HtmlSlicer/TypographyStyleInjector/HtmlHighlightInjector/_PageVerticalAligner/_DualSpreadAligner **全部原样复用,零改动**。这是本方案的核心价值——Q8-Q12 刚修好的分页/边距逻辑一行都不动。

### A2 — MD/TXT 加载器(app 层)

新增两个加载器,把文件转成 `List<HtmlChapterSource>`:

- **`MarkdownBookLoader.load(Uint8List bytes) → List<HtmlChapterSource>`**:
  - UTF-8 解码(失败降级 latin1)
  - 按 `^#{1,2}\s` 正则切章(`#` 与 `##` 都是切章点;`###` 及以下不切,归入当前章)
  - 每章 body 用 `markdown` 包 `markdownToHtml()` 转 HTML
  - 第一个标题前的内容:若有实质内容,归入 title="前言" 的首章;无则丢弃
  - 无任何 `#`/`##` 标题:整篇单章,title=文件名(去扩展名)
- **`TextBookLoader.load(Uint8List bytes) → List<HtmlChapterSource>`**:
  - UTF-8 解码(失败降级 latin1)
  - 整篇按空行分段,每段包 `<p>...</p>`;连续空行合并
  - 单章,title=文件名(去扩展名)

加载结果经 `reader_engine_provider` 路由,喂给 `HtmlChapterReaderEngine`。

### A3 — `reader_body.dart` 的 `is` 检查保持兼容

**关键约束**:`reader_body.dart` 的 12 处 `engine is ConcreteEpubReaderEngine` 检查**不改**(降低 R2 风险)。

**实现方式**:让 `HtmlChapterReaderEngine` 成为 `ConcreteEpubReaderEngine` 的**基类**(继承),或让 `ConcreteEpubReaderEngine` 的实例在 MD/TXT 场景下也能被构造。具体:
- `HtmlChapterReaderEngine` 作为基类,持有渲染核心
- `ConcreteEpubReaderEngine extends HtmlChapterReaderEngine`,追加 EPUB 文件加载
- `reader_engine_provider` 对 MD/TXT 直接构造 `HtmlChapterReaderEngine`(基类),对 EPUB 构造 `ConcreteEpubReaderEngine`(子类)
- 12 处 `is ConcreteEpubReaderEngine` 改为 `is HtmlChapterReaderEngine`(基类检查,EPUB 子类与 MD/TXT 基类都满足)

**统一检查类型**:`is HtmlChapterReaderEngine`。grep 全量替换 + 逐处核对,确保 12 个 gate 全部覆盖。

### A4 — 新增 `markdown` 依赖

- `reader_engine_epub_view/pubspec.yaml` 加 `markdown: ^7.0.0`(BSD-3-Clause,Dart 官方维护)
- `NOTICE` 的 `## 运行时依赖` 加 `markdown (BSD-3-Clause) - https://pub.dev/packages/markdown`
- 不引入 `flutter_markdown`(我们走 md→html→fwfh,不用其 widget)

### A5 — 格式检测:扩展名优先(无 magic bytes)

MD/TXT 没有可靠的 magic bytes(`.md`/`.txt` 都是纯文本,UTF-8/ASCII 无固定前缀)。检测策略:
- `BookFormatDetector.detect`:在现有 magic bytes 检查前,先按扩展名短路(`.md`→markdown, `.txt`→text)
- 放宽 `bytes.length < 5` guard 到 `< 4`(容纳极短 txt)
- 注意:扩展名检测必须放在 PDF(`%PDF-`)/EPUB(`PK`)magic 检查**之后**,避免误把同名二进制文件当文本(如 `report.pdf.txt` 这种极端 case,以扩展名最后一段为准,已是 `p.extension()` 的行为)

## 7. 决策依据(为何复用 EPUB 管道而非新建独立渲染器)

三个 Explore agent 的结论一致指向"复用":

1. **EPUB 的 `Paginator` 输入是 HTML,内部转 plain text 测量**(`paginator.dart:63` 调 `htmlToParagraphs`)。MD→HTML 后可直接喂入,TXT 包 `<p>` 后同理。零适配。
2. **`HtmlSlicer`/`TypographyStyleInjector`/`HtmlHighlightInjector` 都操作 HTML 字符串**,与格式无关。
3. **PDF 模式不适用**:PDF 走 pdfrx 原生 `PdfViewer`,完全不同的渲染模型(页固定布局、原生文本选区)。MD/TXT 是流式文本,本质同 EPUB。

新建独立渲染器(如用 `flutter_markdown`)意味着**重写分页/高亮/双页/缩进/版心对齐**全部逻辑,工作量是复用方案的 5-10 倍,且行为会与 EPUB 不一致(用户在 MD 书里无法用 EPUB 的高亮/双页/进度记忆)。复用方案保证全格式体验统一。

## Root Causes (verified by code trace)

### Bug A — 双页/分页渲染底部溢出（黄黑斑马线）

**用户原话**：「在底部看到一个斜着的黄黑色斑马线图片，还有一排小字 bottom
overflowed by 14 pixels」

**根因**（`reader_engine_epub_view/lib/epubx_renderer.dart:836-940` 的 `_buildPaged`）：

每个 PageView 页面被赋予**固定高度** = PageView viewport 高度（即 reader stack 的
全部可用高度）。页内容是 `Padding(EdgeInsets.all(margin)) > HtmlWidget`（单页）或
`Row[ Expanded(Padding>HtmlWidget), SizedBox(gutter), Expanded(Padding>HtmlWidget|SizedBox) ]`
（双页）。`HtmlWidget`（flutter_widget_from_html 0.15.3）渲染出的实际高度与
`Paginator`（`TextPainter` 测量）算出的高度**存在系统性误差**——代码注释已自认
（epubx_renderer.dart:833-835）：

> "HtmlWidget 的 line-height/字间距 与 TextPainter 测量基准不完全一致，实测在常用
> 排版下误差 < 1 行"

在**双页模式**下这个误差被放大：测量宽度 halve（减 gutter 后对半），换行数对半宽
更敏感，HtmlWidget 的 line-height/font-metrics 偏差累计后某页真实高度 > 测量高度，
即 > 页面固定高度 → 该页内容在 cross-axis（垂直方向）溢出 → Flutter 抛 RenderFlex
overflow assertion → 渲染黄黑斑马线（overflow indicator），文字 "bottom overflowed
by N pixels"。

**为何 narrow（单页）模式没暴露**：单页模式宽度更大、换行误差更小、且单页模式下每页
内容也受同样的固定高度约束——只是误差通常 < 半行，临界页偶尔也溢出，但用户在 narrow
下没注意到；双页模式让溢出从"偶发"变成"稳定复现"。**这是 M2.9 引入的可见回归。**

**为何不是 ReaderProgressBar 遮挡**：进度条是 `Positioned(bottom:0)` overlay，不参与
PageView 的 layout 约束链（它是 Stack sibling，不是 Column child）。它确实遮住内容
底部 ~36px（视觉遮挡，不影响 layout），但**不是** RenderFlex overflow 的来源。
overflow 是 PageView 内部某页的 RenderFlex（Row 的 cross-axis）自己溢出。

### Bug B — 目录 / 笔记跳转失效

**用户原话**：「现在点击目录不能正常跳转了，摘录的笔记也不能正常跳转了」

**根因有两层**：

#### B1（笔记/摘录跳转）：双页模式下 spread index 换算错误

`_onAnnotationTap`（reader_body.dart:534-566）调用 `ScrollToOffsetService.scrollToCharacterOffset`
（scroll_to_offset.dart:35-61），传入 `pageBreaks: engine.currentChapterPageBreaks`。
该 service 的 `_findPageForOffset`（line 63-68）返回的是**break 索引**（单页模式下 = 页号）。
然后在 line 60 调 `pageController.jumpToPage(pageIdx)`。

**但在双页模式下**（`_buildPaged` 的 `itemCount = (breaks.length+1)~/2`），
PageController 的 page 是**spread 索引**，不是 break 索引。`jumpToPage(breakIdx)`
当 `breakIdx >= spreadCount` 时抛
`'PageController.page cannot be greater than itemCount'` assertion → 跳转崩溃 →
"笔记不能跳转"。即使 breakIdx 恰好 < spreadCount，也会跳到错误的 spread（页面对
不上高亮位置）。

#### B2（目录跳转）：缺 settle wait + 双页溢出连锁

`ReaderTocDrawerWrapper.build`（reader_drawer_builders.dart:48-66）的 `onSelect`
只调 `engine.gotoTocEntry(entry)` + `Scaffold.closeDrawer()`，**没调**
`_awaitChapterSettledAndLayout()`（它是 reader_body 的私有方法，wrapper 访问不到）。
`gotoTocEntry` → `gotoLocator` CFI 分支会 emit state 触发 rebuild → 新章首页。

单页模式下这能 work（rebuild 后 PageView 自然落在 page 0）。但双页模式下：
1. rebuild 触发 `_buildPaged` 的 LayoutBuilder 重跑 → 如果新章首页内容触发 Bug A
   的 overflow assertion，整页 rebuild 异常 → TOC 跳转视觉上"卡住"或红屏。
2. 即使没溢出，TOC 跳转后没 jumpToPage，controller 可能停在旧章的某个 spread 索引
   上，新章 itemCount 不同 → 越界。

两条路径都因 M2.9 双页模式而失效。

### Bug C — 书签页报错 + 无添加入口

**用户原话**：「书签页面还是报错，且没有地方来添加书签。」

**根因有两层**：

#### C1（添加书签无入口）：chrome 隐藏时无 fallback

添加书签的**唯一入口**是 `ReaderScaffold._buildChrome`（reader_scaffold.dart:254-）
AppBar 里的 `IconButton(Icons.bookmark_add_outlined)`，`onPressed: widget.onAddBookmark`。
但 `_buildChrome` 整体被 `if (ui.chromeVisible)`（reader_scaffold.dart:188 附近）gate。

`chromeVisible` 默认值（reader_ui_controller.dart:42）是 `false`；只有
`ReaderUiState.defaults()`（line 52-65）在桌面平台（windows/macOS/linux）设为 `true`。
**但**：进入全屏（`toggleFullscreen`，line 112-125）会把 `chromeVisible` 置 false；
用户点 chrome 切换（double-tap center / 全屏图标）也会变 false。一旦 chrome 隐藏，
整个 AppBar（含添加书签按钮）消失，**没有任何 fallback 入口**（无 FAB、无快捷键、
无右键菜单）→ "没有地方来添加书签"。

经 grep 确认（`grep -rn "FloatingAction\|FAB\|bookmark_add\|Ctrl.*B\|LogicalKey.*b"`）：
全代码库无其它 add-bookmark 入口。

#### C2（书签页报错）：与 Bug B 同根因的跳转崩溃 / provider 错误态

`ReaderBookmarkList`（reader_bookmark_list.dart:55-64）的 `error:` 分支会显示红色
"书签加载失败：$e"。可能触发路径：

- **跳转崩溃**：`_onBookmarkJump`（reader_body.dart:834-879）调 `engine.gotoLocator`
  （CFI 分支）→ 跨章 emit → rebuild → 双页溢出异常（Bug A）或 spread 越界（Bug B1）→
  被外层 try-catch 吞 → 用户看到 "跳转失败" SnackBar（不是"书签页报错"）。
- **provider error 态**：`bookmarkControllerProvider`（autoDispose，line 52-57）在
  `bookId == null` 时返回空 state，否则订阅 `repository.watchForBook`。如果 reader
  打开时 `currentBookIdProvider` 暂时为 null（路由参数 race）→ state 短暂 loading →
  切回 data，正常。除非 DB 迁移失败，否则不会稳定 error。

**最可能**：用户看到的是书签 tab 内点击书签后 SnackBar "跳转失败"（Bug B 连锁），
或 drawer 书签 tab 在 add 流程因 chrome 隐藏无法完成时感知为"报错"。需用户进一步
提供红色错误文字精确定位；本次先修 Bug B（根因）+ C1（入口），C2 大概率随之消失。

## Goals

1. **Bug A**：双页/单页分页模式下不再出现 RenderFlex bottom overflow。HtmlWidget 与
   TextPainter 的高度误差被吸收，不抛 assertion。
2. **Bug B**：目录章节跳转、笔记/摘录跳转、书签跳转在**双页模式**下都正确落到目标
   spread（左右两页中正确的一对）。
3. **Bug C**：chrome 隐藏时仍有可见的"添加书签"入口（无 chrome 也能加书签）。
4. **每个修复配回归测试**（如 B1 的 spread 换算、A 的 overflow 吸收）。

## Non-Goals

- 不改 Paginator 的测量算法（仍用 TextPainter），只在渲染层吸收误差（见 A1）。
- 不持久化书签快捷键 / 不加书签编辑（仍 long-press delete，编辑延后）。
- 不动 PDF 双页（独立 toggle，不经本次自动双页路径）。
- 不改 M2.9 的双页触发阈值（≥1100px）或页码格式（"3-4 / 12"）。

## Design Decisions

### A1（决策）— 页内容用可滚动容器吸收高度误差，而非改测量基准

**选项对比**：

| 方案 | 实现 | 优点 | 缺点 |
|------|------|------|------|
| (a) 改 Paginator 用 HtmlWidget 测量 | 让 `_measureHeight` 渲染 HtmlWidget 取高度 | 测量与渲染完全一致 | 重写 Paginator，HtmlWidget 测量需 Offstage 渲染、性能差、复杂度高 |
| (b) Paginator 高度减安全 buffer | `usableHeight = viewport.height - 2*margin - 1*lineHeight` | 1 行改动 | buffer 难定（行高随字号变），可能留空白底 |
| (c) 页内容包 `SingleChildScrollView` | `buildSinglePage` 返回 `SingleChildScrollView(physics: NeverScrollableScrollPhysics(), child: Padding>HtmlWidget)` | 误差自然吸收（不溢出即不滚，溢出可滚），零测量改动 | 双页孤页滚动行为需约束 `physics: NeverScrollableScrollPhysics` 避免与 PageView 手势冲突 |

**选 (c)**：最小侵入、零测量改动、对 HtmlWidget/TextPainter 的固有误差完全免疫。
代价：极个别页（误差较大时）可竖向微滚，但绝不抛 assertion。PageView 用
`NeverScrollableScrollPhysics` 确保子页滚动不干扰翻页手势。这是工业界阅读器
（如 readium）的常见做法——分页边界本就是近似，页面允许小幅内部滚动兜底。

与现有 `_buildScroll`（scroll 模式已用 `SingleChildScrollView` + `_scrollController`，
epubx_renderer.dart:807）模式一致，paged 模式只是不挂 controller、锁 NeverScrollable。

### B1（决策）— `ScrollToOffsetService` 接收 `dualPageMode`，换算 spread 索引

`scrollToCharacterOffset` 增加 `bool dualPageMode = false` 参数。paged 分支：

```dart
final breakIdx = _findPageForOffset(pageBreaks, targetOffset);
final targetPage = dualPageMode ? breakIdx ~/ 2 : breakIdx;
// 防御 clamp（itemCount 未传入，由 PageController 自身 clamp；但显式 clamp 更稳）
pageController.jumpToPage(targetPage);
```

调用方（`_onAnnotationTap`、`_maybeHandleInitialLocator`）从
`engine.dualPageMode` 读取传入（engine 是 ConcreteEpubReaderEngine 时读其 getter）。
这样不动 service 的现有签名契约（新参数有默认值，旧测试不破）。

### B2（决策）— TOC 跳转也走 settle wait

把 `_awaitChapterSettledAndLayout` 的等价逻辑下沉：`ReaderTocDrawerWrapper` 拿不到
reader_body 的私有方法，但 `engine.chapterSwitchSettled` 是公开 Future。在
`onSelect` 里：

```dart
onSelect: (entry) async {
  await engine.gotoTocEntry(entry);
  await engine.chapterSwitchSettled;
  if (context.mounted) Scaffold.of(context).closeDrawer();
},
```

`closeDrawer` 放在 await 之后避免 drawer 提前关掉导致 context 失效。不需 endOfFrame
（TOC 跳转不像笔记那样需要 jumpToPage，rebuild 后 PageView 自然落在 page 0）。

### C1（决策）— 添加书签入口下沉到永久可见的浮层按钮

**选项对比**：

| 方案 | 实现 | 优点 | 缺点 |
|------|------|------|------|
| (a) chrome 隐藏时显示角落书签 FAB | `_buildReaderStack` 的 Stack 加 `Positioned(bottom: 56, right: 16)` 的 `FloatingActionButton(onPressed: onAddBookmark)`，仅 `!ui.chromeVisible` 时显示 | chrome 隐藏时唯一可见入口，不挡阅读 | 多一个浮层元素 |
| (b) 双击 center 唤出 chrome 再点 | 复用现有 `_toggleChrome` | 零新增 widget | 用户不知道要双击（无提示），体验差 |
| (c) 加 Ctrl+B 快捷键 | `HardwareKeyboard` 监听 | 桌面端高效 | 移动端无效，且与现有键盘翻页体系混 |

**选 (a)**：与 Bug A 修复后的布局（进度条在底）协调——FAB 浮在进度条右上方，
chrome 隐藏时是唯一 chrome-like 入口，chrome 显示时不重复（避免和 AppBar 按钮撞）。
图标用 `Icons.bookmark_add_outlined` 与 AppBar 一致。FAB 放在 `_buildReaderStack`
的 Stack（窄宽屏共用），位置 `right:16, bottom:56`（避让底部进度条 ~36px + 间距）。

## Architecture Decisions

- **不动 `ReaderEngine` 接口**：`dualPageMode` getter 已在 M2.9 加到
  `ConcreteEpubReaderEngine`，service 直接读，无需扩接口。
- **`ScrollToOffsetService` 扩参而非新方法**：`dualPageMode` 有默认值 `false`，
  所有现有调用方（含测试 fake）不受影响，仅 2 个真实调用点改。
- **测试策略**：
  - A：新增 `epubx_renderer_paged_overflow_test.dart`，构造一个 TextPainter 测量
    恰好满高、但 HtmlWidget 渲染略高的 HTML，验证不再抛 overflow assertion。
  - B1：扩展 `scroll_to_offset_test.dart`，验证双页模式下 jumpToPage 收到 breakIdx~/2。
  - B2：扩展 `reader_drawer_test.dart`，验证 onSelect 调 gotoTocEntry 后 await
    chapterSwitchSettled。
  - C1：新增 `reader_body_bookmark_fab_test.dart`，验证 chrome 隐藏时 FAB 存在、
    点击触发 `_onAddBookmark`。
- **不重建 exe 直到 3 个 bug 测试通过 + analyze 干净**。

## Risks

1. **(c) SingleChildScrollView 与 PageView 手势冲突**：`NeverScrollableScrollPhysics`
   兜底，但需测试双页孤页（右页空）不出现异常手势传播。
2. **TOC settle wait 改变 drawer 关闭时序**：原 onSelect 立即 closeDrawer，
   改成 await 后关。若用户连点多个 TOC 条目，第二个点进来 drawer 还没关——可接受
   （第二次 onSelect 会重新 await，drawer 自然停在最后选中）。
3. **FAB 在宽屏 sidebar 布局的位置**：宽屏是 `Row(sidebar, Expanded(stack))`，
   FAB 应在 Expanded 内的 stack 右下，不跨到 sidebar。FAB 加进
   `_buildReaderStack` 的 Stack（共用窄宽）即满足此约束。

## Success Criteria

- 用户在 ≥1100px 双页模式下：翻页不再出现底部黄黑斑马线。
- 用户点击目录章节：正确跳到该章双页首页。
- 用户点击笔记条目：正确跳到高亮所在 spread（左右页含高亮）。
- 用户全屏/chrome 隐藏时：右下可见书签 FAB，点击弹 dialog，可添加书签。
- 全部测试通过（含新增回归测试），`dart.bat analyze` 无 error。

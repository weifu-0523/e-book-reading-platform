## 1. 目标

M2.0a 已超出原 roadmap 承诺，**双向 push+pull + outbox 持久化 + RateLimiter + LWW applier 全部就位**。M2.0b 不再补底层，只做 3 件事：

1. **让 LWW 决定可见**：冲突发生时落日志，用户可在 status page 看到 winner/loser/diff preview
2. **让 sync 自动跑**：默认 5 分钟周期 + App 生命周期感知（前台拉、后台停）
3. **让 outbox / 冲突表不无限长**：7 天 / 30 天滚动清理

**完成态**：
- 任意 sync 触发后，conflict log 自动写入；用户可在 SyncStatusPage 看到最近 30 天冲突
- SyncController 启动后自动开始周期 sync；用户可配置 1/5/15/30 min 或 off
- App 进后台 → 暂停；回前台 → 立即拉一次再恢复周期
- outbox 推送成功的行 7 天后清；conflict log 30 天后清

**不在范围**（推迟到 v2）：
- 交互式冲突解决（用户手动选 winner）
- 字段级 merge
- 同书问答 / AI 章节导读（属于 Spiral 4/5）
- Android APK 打包（phase 3）

### 关键数据流

**1. 冲突检测**：
```
pull 阶段 → WebDavSyncEngine → RemoteRecordApplier.apply(rec)
  → existing != null && !rec.mtime.isAfter(localMtime)
  → sink.record(localMtime, rec.mtime, rec.payload, ...)
  → return false (落 LWW 不替换)
```

**2. 后台触发**：
```
Timer.periodic(5min) → _tickSafe
  → if isRunning return (防叠加)
  → if cooldownActive return (限流保护)
  → onTick() = SyncController.syncNow()
  → 成功: 清 cooldown + purge 旧数据
  → 失败: 设 cooldown 5 分钟
```

**3. 生命周期**：
```
AppLifecycleState.paused → scheduler.pause() (cancel timer)
AppLifecycleState.resumed → scheduler.resume()
  → 立即 await onTick() (回前台拉一次)
  → 重建 Timer
```

**4. 清理**（syncNow 成功分支末尾）：
```
final now = clock();
database.syncOutboxDao.purgePushedBefore(now - Duration(days: 7));
database.syncConflictsDao.purgeBefore(now - Duration(days: 30));
```
"7 天" / "30 天" 一律按 `Duration(days: N)` 严格 24×N 小时计算，不用 calendar days（避免月末/跨年歧义）。

## 4. 数据模型：`sync_conflicts` 表

### Schema

```dart
@DataClassName('SyncConflictEntry')
class SyncConflicts extends Table {
  IntColumn get id => integer().autoIncrement()();
  TextColumn get recordId => text()();
  TextColumn get recordType => text()();  // 'annotation' | 'bookNote' | 'readingProgress'
  DateTimeColumn get localMtime => dateTime()();
  DateTimeColumn get remoteMtime => dateTime()();
  TextColumn get winnerDevice => text()();  // 永远是 local deviceId（LWW 语义）
  TextColumn get loserDevice => text()();   // remote snapshot 来源 deviceId
  DateTimeColumn get detectedAt => dateTime()();
  TextColumn get payloadPreview => text()();  // 远端 payload JSON，截 200 字
}
```

### 索引

```sql
CREATE INDEX idx_sync_conflicts_detected_at ON sync_conflicts(detected_at DESC);
```
理由：UI 按 `detected_at DESC` 滚动；purgeBefore 也按 `detected_at` 扫描。

### 冲突写入时机

仅 `RemoteRecordApplier`：

| apply 分支 | 现行为 | 改造后 |
|---|---|---|
| `_applyAnnotation` existing!=null && !remote.isAfter(local) | return false | 先 sink.record(...)，再 return false |
| `_applyBookNote` 同上 | return false | 同上 |
| `_applyReadingProgress` 同上 | return false | 同上 |
| `_applyBook` existing!=null（books 无 updated_at） | return false | **不记** — book 几乎不冲突 |
| `_apply*` deleted tombstone 但 local 是 newer | return false | sink.record(...) 标 deleted conflict |

### ConflictSink 接口

```dart
abstract class ConflictSink {
  Future<void> record({
    required String recordId,
    required SyncRecordType recordType,
    required DateTime localMtime,
    required DateTime remoteMtime,
    required String remoteDeviceId,
    required Map<String, dynamic> remotePayload,
  });
}
```

### remoteDeviceId 流转

`RemoteRecordApplier` 在 `pullOnly` 的 file loop 外只创建一次，但每个 file 对应不同 remoteDeviceId。解决方案：**applier 持有可变 `currentRemoteDeviceId` 字段**，`pullOnly` 在解析每个 file 前调 `applier.setRemoteDevice(fileDeviceId)`。

```dart
// web_dav_sync_engine.dart pullOnly 改造
final applier = RemoteRecordApplier(database, conflictSink: sink);
for (final file in files) {
  if (file == '$deviceId.jsonl') continue;
  final fileDeviceId = file.replaceAll('.jsonl', '');
  applier.currentRemoteDeviceId = fileDeviceId;  // 切换上下文
  final body = await _rateLimiter.run(...);
  // ...
}
```

替代方案（拒绝）：每 file 创建新 applier — 失去 existing 查询的潜在缓存优化；不采用。

class NullConflictSink implements ConflictSink {
  const NullConflictSink();
  @override
  Future<void> record({...}) async {}
}
```

### DaoConflictSink 实现

```dart
class DaoConflictSink implements ConflictSink {
  DaoConflictSink(this._dao, this._localDeviceId);
  final SyncConflictsDao _dao;
  final String _localDeviceId;

  @override
  Future<void> record({...}) async {
    final preview = jsonEncode(remotePayload);
    await _dao.insert(
      recordId: recordId,
      recordType: recordType.name,
      localMtime: localMtime,
      remoteMtime: remoteMtime,
      winnerDevice: _localDeviceId,  // 永远 local
      loserDevice: remoteDeviceId,
      payloadPreview: preview.length > 200
          ? '${preview.substring(0, 200)}…'
          : preview,
    );
  }
}
```

**winnerDevice 简化**：因 `apply` 返回 false 必然意味着 local 更新或相等，故 winner 永远是 local，loser 永远是 remote snapshot 来源。接口只接 `remoteDeviceId`，简化测试与调用方。

### 边界

1. **同 mtime 但内容不同**：当前 `isAfter` 严格，相等时不替换 → 进 conflict log。时钟漂移的可视化。
2. **同一 record 多次冲突**：每次 sync 都记一行，不折叠。30 天滚动清理保证上限。

## 5. 后台定时与生命周期

### BackgroundSyncScheduler

```dart
class BackgroundSyncScheduler {
  BackgroundSyncScheduler({
    required this.onTick,
    required DateTime Function() clock,
    Duration initialInterval = const Duration(minutes: 5),
  }) : _clock = clock, _interval = initialInterval;

  final Future<void> Function() onTick;
  final DateTime Function() _clock;
  Timer? _timer;
  Duration _interval;
  bool _isRunning = false;
  DateTime? _lastErrorAt;
  static const _cooldown = Duration(minutes: 5);

  void updateInterval(Duration interval);  // 0 = stop
  void pause();                             // cancel timer
  Future<void> resume();                    // await onTick + reset timer
  Future<void> _tickSafe();                 // guard + cooldown
}
```

### 关键不变量

- **`_isRunning` guard**：避免 Timer tick 与手动 syncNow 叠加（rate limiter 已节流，但网络请求重叠仍浪费电）
- **`updateInterval`**：从 settings 改 interval 时调；先 cancel 旧 Timer，再用新 Duration 启动（除非 0 = off）
- **`resume` 行为**：先 `await onTick()`（不立即重建 Timer），再 `_resetTimer()`；保证回前台 1s 内拉一次最新
- **`_cooldown`**：onTick 抛错后 5 分钟内不再自动 tick（手动 syncNow 不受约束）

### SyncController 整合

```dart
class SyncController extends StateNotifier<SyncState>
    with WidgetsBindingObserver {
  late final BackgroundSyncScheduler _scheduler;

  @override
  void didChangeAppLifecycleState(AppLifecycleState state) {
    if (state == AppLifecycleState.resumed) _scheduler.resume();
    else if (state == AppLifecycleState.paused) _scheduler.pause();
  }

  Future<void> setInterval(Duration interval) async {
    await _intervalPref.save(interval);
    _scheduler.updateInterval(interval);
  }

  Future<void> syncNow() async {
    // ...现有逻辑...
    if (result.success) {
      await database.syncOutboxDao.purgePushedBefore(
        _clock().subtract(const Duration(days: 7)));
      await database.syncConflictsDao.purgeBefore(
        _clock().subtract(const Duration(days: 30)));
    }
  }
}
```

### Init 时机

1. SyncController 构造：读 interval pref → 创建 scheduler → startTimer
2. `WidgetsBinding.instance.addObserver(this)` 注册生命周期
3. `dispose()`：`removeObserver` + `scheduler.pause()`

### 电耗考量

- 默认 5 分钟 — 远低于浏览阅读一段文字的停留时间，体验上"实时"
- off 选项 — 节电用户/限流敏感用户保留 escape hatch
- `paused` 不 tick — 不让 Android 后台 Doze 模式强制 keep-alive

### 双层节流

- RateLimiter（既有）：WebDavClient 层，2s 间隔 — 防 R1（30 次/分钟）
- Scheduler（新）：SyncController 层，分钟级 — 防过频触发

## 7. 错误处理与边界

### 失败分类与响应

| 场景 | 现状 | M2.0b 改造 |
|---|---|---|
| **网络断** | catch generic → error + e.toString() | 加 connectivity_plus：无网 → SyncStatus.offline + 不弹错误 banner |
| **401 凭据错** | WebDavException(401) → error | 同步显式状态 → SyncStatus.error + lastMessage='syncAuthFailed' + 跳 settings 提示 |
| **429 限流** | 已识别 → 'syncRateLimitedWarning' | scheduler 自动 5 分钟 cooldown |
| **5xx 服务端** | generic error | 重试 1 次（RateLimiter 内部已重试），仍失败 → error 状态保留 |
| **Applier parse 失败** | 跳过该行 | 同 M2.0a — 不影响其他 record |
| **Conflict sink 写失败** | 不存在 | catch 内部 → 仅 log，**不影响 sync 成功** |
| **冲突日志 purge 失败** | 不存在 | 同上，catch 静默 |

### Scheduler cooldown 逻辑

```dart
Future<void> _tickSafe() async {
  if (_isRunning) return;
  if (_lastErrorAt != null &&
      _clock().difference(_lastErrorAt) < _cooldown) {
    return;  // 限流冷却中
  }
  _isRunning = true;
  try {
    await onTick();
    _lastErrorAt = null;
  } catch (_) {
    _lastErrorAt = _clock();
    rethrow;
  } finally {
    _isRunning = false;
  }
}
```

**手动 syncNow 不受 cooldown 约束** — 用户主动操作不能被自动限流拦。

### connectivity_plus 新增依赖

- 包大小 ~50KB，Windows/Android 都支持
- UX 收益明显（无网秒判 offline，不等 timeout）
- 用法：`Connectivity().onConnectivityChanged.listen(...)` 监听 + `checkConnectivity()` 主动查
- SyncController 在 syncNow 起始查一次：`none` → 直接 SyncStatus.offline，跳过 engine.sync()
- **Windows fallback**：connectivity_plus 在 Windows 桌面会返回 `ConnectivityResult.wifi`/`ethernet`/`none`，但部分虚拟网卡环境可能误报。策略：connectivity 判定不阻塞 sync — 仅作为 "快速 offline 提示"，真实网络错误仍由 WebDavClient try/catch 兜底（既有行为不变）。

### 冲突日志保留

- 同一 (recordId, type) 多次 conflict 全部记录（不折叠）
- 30 天前自动 purge（syncNow 成功后）
- 用户手动 clear 全部删除

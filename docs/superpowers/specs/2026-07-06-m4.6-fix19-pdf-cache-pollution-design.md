# M4.6-fix19 — PDF 加载卡死根治（pdfrx sourceName cache pollution）

**日期**：2026-07-06
**类型**：bugfix（根治历史 PDF-1 系列）
**前置**：M4.6-fix9 / fix13 / fix18（均为缓解，未根治）

---

## Context（为什么做）

用户报告："昨天 PDF 双页测试失败后锁死单页，但**今天 PDF 不能正常加载**。"

commit `9c6ffad`（fix11~18）的"遗留"区段已记录 PDF-1/PDF-2 两个症状：
- **PDF-1**：第 1 次 openFile 29MB PDF 成功 → 关书 → 第 2 次开同 PDF 30s TIMEOUT
- **PDF-2**：当前 baseline"不能加载 PDF"

fix9/fix13/fix18 都尝试过：
- fix9：双 PdfViewer 共享 sourceName（失败，仍卡死）
- fix13：dispose timeout 3s→10s + 1.5s buffer（缓解，未根治）
- fix18：试"不调 dispose"（实测失败，已回退）

所有方案都在 dispose 时序上做文章，**但都没找到真因**。

---

## 根因分析（smoking gun）

### 证据 1：zhiyue_pdf.log 时间线

```
2026-07-05T22:39:14  openFile start: 75d7fa61...pdf
2026-07-05T22:39:14  openFile bytes read: 29055673 bytes
                     （无后续日志 — 卡在 PdfDocument.openData）
2026-07-05T22:58:51  openFile start: 同一 PDF
2026-07-05T22:58:51  openFile bytes read: 29055673 bytes
                     （无后续日志 — 卡死）
2026-07-06T23:40:52  openFile start: 同一 PDF（用户今天测试）
2026-07-06T23:40:52  openFile bytes read: 29055673 bytes
                     （无后续日志 — 仍卡死）
```

**所有真实加载尝试，都卡在 `PdfDocument.openData(_bytes!)` 这一行**——bytes 读成功，但 pdfrx 打开文档的 Future 永远不 complete。

### 证据 2：pdfrx 内部 cache 机制

`pdfrx_engine-0.4.3/lib/src/native/pdfrx_pdfium.dart:645-647`：

```dart
static String _sourceNameFromData(Uint8List data) {
  return 'data%${sha256.convert(data)}';
}
```

当 `PdfDocument.openData` **不传 sourceName** 时，pdfrx 用 `'data%${sha256(data)}'` 作 sourceName。
**同一 PDF 文件字节不变 → SHA-256 不变 → sourceName 跨会话稳定**。

`pdfrx-2.4.4/lib/src/pdf_document_ref.dart:92-97`：

```dart
static final _listenables = CanonicalizedMap<PdfDocumentRefKey, PdfDocumentRef, PdfDocumentListenable>(
  (ref) => ref.key,
);

PdfDocumentListenable resolveListenable() =>
    _listenables.putIfAbsent(this, () => PdfDocumentListenable._(this));
```

`_listenables` 是**进程级 static CanonicalizedMap**，按 sourceName 缓存 PdfDocumentListenable。

### 因果链

1. 7-5 22:39 第 1 次 openFile → sourceName = `data%<sha256>`
2. 加载过程中（pdfrx 内部线程池/FPI 异步）卡死，listenable 处于 broken 状态
3. broken listenable 残留在 `_listenables` cache
4. 7-5 22:58 / 7-6 23:40 第 2/N 次 openFile 同 PDF
5. **同 SHA-256 → 同 sourceName → `putIfAbsent` 命中 broken cache entry**
6. 返回已 broken 的 listenable，`FPDF_LoadMemDocument` 永不返回
7. Dart 侧 Future 永不 complete → 30s timeout

### 为何"昨天第一次能开，今天不能开"

- 昨天第一次：cache 为空 → 新 listenable → 加载成功
- 今天：cache 里有昨天卡死留下的 broken entry → 永远命中 → 卡死

这也解释了 fix18 "不调 dispose" 为何更糟：跳过 dispose 让 listenable 残留更久，cache 更脏。

---

## Goals

1. **根治 PDF 加载卡死**：任意次数开任意 PDF 都能成功（或快速失败，不卡死）
2. **保留单页渲染**：fix10 已锁死单页，fix19 不动这个
3. **最小改动**：一行 sourceName 修复，不引入新风险

## Non-Goals

- 不解决 PDF 双页（fix10 已锁死单页，未来 M4.7 重做）
- 不改 dispose 时序（fix19 后不再依赖 dispose 是否干净）
- 不换 PDF 库（fix19 让 pdfrx 重新可用）

---

## Architecture Decisions

### A1：每次 openFile 生成唯一 sourceName（采用）

**方案**：`_uniqueSourceName = 'zhiyue-pdf-${DateTime.now().microsecondsSinceEpoch}'`

**为什么有效**：
- 每次进书 → 新 key → `_listenables.putIfAbsent` cache miss → 全新 listenable → pdfium 全新 FPDF doc
- 退出再进 → 又是新 key → 永不命中旧 broken cache
- 同进程开不同 PDF → key 不同 → 互不干扰
- 进程退出（main.dart `exit(0)`）→ static cache 自然清空

**代价**：失去跨 PdfViewer 共享文档的内存优化。但智阅是单 PDF 单实例阅读，不存在多 viewer 共享场景，**代价为零**。

**改动位置**（`pdf_renderer.dart`）：
1. `openFile`：`PdfDocument.openData(_bytes!, sourceName: _uniqueSourceName)`
2. `_buildMain`：`PdfViewer.data(bytes, sourceName: _uniqueSourceName, key: ValueKey('pdf-main-$_uniqueSourceName'))`
3. ValueKey 用同一 sourceName 保证 widget 复用稳定

### A2（拒绝）：fork pdfrx 暴露 cache cleanup API

中风险，工作量大，需维护 fork。

### A3（拒绝）：exe 自重启机制

中等工作量，用户体验差（开 PDF 还要重启 exe）。

### A4（拒绝）：换 PDF 库 pdfx/pdf_viewer

工作量大（2-3 天），且 pdfrx 本身没问题，问题在我们没用对 sourceName。

---

## Risks

| Risk | 概率 | 缓解 |
|------|------|------|
| 多 PdfViewer 实例无法共享同一 PdfDocument（内存翻倍） | 极低 | 智阅单 viewer，不存在此场景 |
| microsecondsSinceEpoch 在极端情况撞 key | 几乎不可能 | 1 微秒精度，单用户操作不可能撞 |
| pdfrx 未来版本改 cache 机制 | 低 | sourceName 唯一性是 pdfrx 官方推荐用法（pdf_document.dart:90-91） |

---

## Success Criteria

- **SC1**：进程启动后第 1 次开任意 PDF 成功（1 秒内）
- **SC2**：关书后第 2 次开**同一 PDF** 成功（不再卡死）✨ 这是 fix13~fix18 都做不到的
- **SC3**：开 PDF → 关书 → 开**不同 PDF** → 再回开第一个 PDF，全部成功
- **SC4**：dart analyze 全过
- **SC5**：日志能看到 `openFile unique sourceName: zhiyue-pdf-<timestamp>`

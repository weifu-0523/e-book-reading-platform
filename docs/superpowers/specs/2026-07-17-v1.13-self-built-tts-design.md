# v1.13 自研 Android TTS Plugin 设计

**日期**：2026-07-17
**目标版本**：v1.13.0-alpha
**前置**：v1.12.3-alpha（custom MainActivity 跳过 audio plugin 注册，Android TTS UI 在但 no-op）
**取代**：`docs/superpowers/specs/2026-07-16-tts-design.md` 的 Phase 3 移动端后台/锁屏部分（flutter_tts + audio_service + audio_session 三件套）
**作者**：weifu0523 + Claude（brainstorming + subagent-driven）

---

## 背景与动机

v1.12.0-alpha 引入 `flutter_tts` + `audio_service` + `audio_session` 三件套实现移动端 TTS。这三个 plugin 在国产 ROM（华为 / 小米 / OPPO / vivo / Honor，Android 12+）的 `onAttachedToEngine` 阶段就绑定 system service（`new TextToSpeech(...)` / `AudioManager.registerAudioDeviceCallback(...)` / foreground service bind），触发启动期 kill。

v1.12.1/2/3-alpha 进行了 4 次 P0 修复尝试：

| # | 版本 | 策略 | 结果 |
|---|---|---|---|
| 1 | v1.12.1-alpha | lazy init audio_service 在 Dart `main()` 内 | 失败（plugin onAttachedToEngine 早于 main） |
| 2 | v1.12.2-alpha | 删 manifest FGS 声明 + 移除 main.dart audio init | 失败（manifest 不是触发点） |
| 3 | v1.12.3-alpha-exp2 | patch pub-cache flutter_tts + audio_session | 失败（3 plugin 各有多个 init 路径） |
| 4 | v1.12.3-alpha-exp3 | custom MainActivity 跳过 plugin 注册 | **成功**（真机验证 2026-07-17） |

v1.12.3-alpha 真正修复了启动 crash，但代价是 **Android TTS 完全失效**（UI 按钮在但点击无反应）。本设计文档解决：如何在保持启动稳定的前提下，**恢复 Android TTS 全部能力**（基本朗读 + 通知栏 + 后台播放 + 锁屏 + 蓝牙）。

## 核心教训（已记入 memory）

> **不要试图 patch 第三方 plugin 内部（pub-cache patch 不可持续 + 每个 plugin 有多个 init 路径），应在 plugin registration 层 block。**
>
> 自研 plugin 时，**`onAttachedToEngine` 必须完全空实现**——所有系统绑定（TextToSpeech / MediaSession / AudioFocus / startForeground）只能延迟到用户首次操作时（user gesture）。

## 目标

恢复 v1.12.0-alpha 在 Android 上承诺的全部 TTS 能力：

| 能力 | 状态 | 实现路径 |
|---|---|---|
| A. 基本朗读（app 在前台） | ✅ 必交付 | 自研 MethodChannel plugin + Kotlin `TextToSpeech` |
| B. 通知栏控件（app 切后台） | ✅ 必交付 | Foreground Service mandatory notification |
| C. 后台播放（屏幕灭 / app 被系统回收后仍读） | ✅ 必交付（**风险点**：FGS manifest 声明需真机验证不 crash） | Foreground Service 保活 |
| D. 锁屏 + 蓝牙耳机按键 | ✅ 必交付 | MediaSessionCompat 注册 |
| 电话打断自动 pause | ✅ 必交付 | AudioFocusRequest + PhoneStateListener/TelephonyCallback |
| 跨设备 last_tts_position 同步 | ✅ 沿用 v1.12 schema v15 `books.last_tts_position` 列 | 不变 |
| Desktop TTS（Windows/macOS/Linux） | ✅ 沿用 flutter_tts | 不变 |
| iOS TTS | ⏸ v1.13 不实现，interface 预留 | TtsService 抽象层保留 iOS Impl 槽位 |

## 非目标

- 不替换桌面端 `FlutterTtsServiceImpl`（Windows SAPI 工作良好）
- 不实现 iOS TTS（v1.14+ 另议）
- 不引入新的 audio framework（ExoPlayer / MediaPlayer 等）
- 不重写 sentence segmenter / chapter iterator（v1.12 现有逻辑沿用）

## 架构

### 三层结构

```
┌─────────────────────────────────────────────────────────┐
│ Dart 层（app/lib/）                                       │
│                                                          │
│  TtsPlaybackController（现有，几乎不动）                   │
│        │ 调 TtsService 接口                                │
│        ▼                                                  │
│  TtsService（interface，现有）                             │
│   ├── FlutterTtsServiceImpl（现有）                       │
│   │   用于 desktop（Windows SAPI via flutter_tts）         │
│   └── SelfBuiltTtsServiceImpl（新）                       │
│       用于 Android（MethodChannel + EventChannel）        │
│       iOS Impl 槽位预留                                   │
└─────────────────────────────────────────────────────────┘
                      │
                      │ MethodChannel: dev.zhiyue.tts/*
                      │ EventChannel:  dev.zhiyue.tts/events
                      ▼
┌─────────────────────────────────────────────────────────┐
│ Kotlin 层（android/app/src/main/kotlin/dev/zhiyue/zhiyue/tts/）│
│                                                          │
│  ZhiYueTtsPlugin（FlutterPlugin + MethodCallHandler）     │
│   - onAttachedToEngine: ✗ NOTHING（关键不变量）           │
│   - init/speak/pause/stop/setRate/... via MethodChannel   │
│        │                                                  │
│        │ startForegroundService(Intent)                   │
│        ▼                                                  │
│  ZhiYueTtsService（Service + MediaSession holder）        │
│   - 持有 TextToSpeech（lazy 构造）                         │
│   - 持有 MediaSessionCompat（锁屏 + 蓝牙按键）             │
│   - 持有 AudioFocusRequest（电话打断）                     │
│   - startForeground(notification) 保活                    │
│                                                          │
│  ZhiYueTtsMediaButtonReceiver（可选）                     │
│   - 路由硬件 media button 到 service                       │
└─────────────────────────────────────────────────────────┘
```

### 核心不变量

1. **`ZhiYueTtsPlugin.onAttachedToEngine` 必须完全空实现**——v1.12.3-alpha 4 次失败的核心教训。任何系统 API 调用（TextToSpeech ctor / AudioManager / MediaSession / startForeground）都会在 plugin 注册期触发国产 ROM 扫描。
2. **所有系统绑定延迟到 `ZhiYueTtsService.onCreate`**——service 在用户首次「朗读」时才 `startForegroundService`（user gesture exemption，符合 Android 12+ FGS 限制）。
3. **`MainActivity.registerSafePlugins` 添加 `ZhiYueTtsPlugin`**，仍然跳过 audio_service / audio_session / flutter_tts 三个旧 plugin（依赖也从 pubspec 移除）。
4. **Desktop 路径完全不动**——继续用 `FlutterTtsServiceImpl`（flutter_tts Windows 端走 SAPI，无 ROM 限制）。

## 数据流

### 2.1 首次「朗读」点击（lazy init）

```
[User] 点 reader 工具栏「朗读」
   ▼
[ReaderController.speakCurrent] → [TtsPlaybackController.play()]
   ▼
[TtsPlaybackController] 检查 _ttsService ready（首次 false）
   ▼
[SelfBuiltTtsServiceImpl.init()]
   ▼ await methodChannel.invokeMethod('init', {language})
[ZhiYueTtsPlugin.onMethodCall("init")]
   ▼ context.startForegroundService(Intent(TtsService))
   ▼ （Android 12+ user gesture exemption：处于 click handler 内，符合）
[ZhiYueTtsService.onCreate()]
   1. new TextToSpeech(context, listener)  ← attach-time 没做，user gesture 后才做
   2. MediaSessionCompat(context, "zhiyue-tts")
   3. AudioFocusRequest.Builder(AUDIOFOCUS_GAIN)
   4. registerPhoneStateListener（电话打断）
   5. startForeground(NOTIFICATION_ID, buildNotification())  ← 保活
   ▼
[ZhiYueTtsService.onStartCommand(SPEAK)]
   tts.speak(text, QUEUE_ADD, params, utteranceId)
   updateMediaSessionPlaybackState(STATE_PLAYING)
   ▼
[EventChannel dev.zhiyue.tts/events] emit {event:"ready"} + {event:"state", state:"playing"}
   ▼
[SelfBuiltTtsServiceImpl] → _stateController.add(TtsState.playing)
   ▼
[TtsPlaybackController] 通知 UI 状态切换为 playing
   ▼
[UI] 「朗读」按钮变 pause 图标，底部 mini-player 出现
```

**关键时间窗**：从 `startForegroundService` 到 `startForeground` 调用必须 ≤ 5 秒（Android 12+ ANR 阈值）。TextToSpeech 构造同步，整个流程 < 100ms，安全。

### 2.2 后续句子的播放

```
[TtsPlaybackController] 当前句播放完成 → 取下一句
   ▼ await ttsService.speakSentence(text, sentenceIdx)
[SelfBuiltTtsServiceImpl.speakSentence] → methodChannel.invokeMethod('speak')
[ZhiYueTtsPlugin] → [ZhiYueTtsService.onStartCommand(SPEAK)]
   ▼ tts.speak(text, QUEUE_ADD, params, utteranceId)
[TextToSpeech.OnUtteranceProgressListener]
   - onStart(utteranceId) → emit {event:"start", utteranceId}
   - onRangeStart(start, end, frame) → emit {event:"progress", start, end, utteranceId}
   - onDone(utteranceId) → emit {event:"done", utteranceId}
   ▼
[EventChannel] → [Dart] → [TtsPlaybackController]
   onDone 触发下一句 / 章节末尾 → 下一章 / 或停止
```

### 2.3 Pause / Resume

Android `TextToSpeech` 原生没有 pause，只能 stop + 记录位置 + 重新 speak（与 audio_service 行为一致）。

```
[User] 点「暂停」
   ▼
[TtsPlaybackController.pause] → [SelfBuiltTtsServiceImpl.pause] → invokeMethod('pause')
[ZhiYueTtsService.onStartCommand(PAUSE)]
   1. tts.stop()
   2. 记录当前 utteranceId + last progress（用于 resume）
   3. updateMediaSessionPlaybackState(STATE_PAUSED)
   4. **不调 stopForeground**（Android 12+ 暂停后 stopForeground 会导致后续 resume 报 ForegroundServiceStartNotAllowedException）
   5. notification 改为 pause 状态
   ▼
[Dart] state → paused

[User] 点「继续」
   ▼ invokeMethod('resume')
[ZhiYueTtsService.onStartCommand(RESUME)]
   用记录的 utteranceId + position 重新 speak（或简化为当前句首重读）
   updateMediaSessionPlaybackState(STATE_PLAYING)
```

### 2.4 Stop / 服务销毁

```
[TtsPlaybackController.stop] → invokeMethod('stop')
[ZhiYueTtsService.onStartCommand(STOP)]
   1. tts.stop()
   2. abandonAudioFocus()
   3. mediaSession.isActive = false
   4. stopForeground(true)（移除 notification）
   5. stopSelf()
   ▼ onDestroy
   tts.shutdown()（释放 native 资源）
   ▼
[EventChannel] emit {event:"state", state:"stopped"}
```

### 2.5 跨章播放

```
[TextToSpeech.onDone] 当前句是章末
   ▼
[TtsPlaybackController._onSentenceDone]
   hasMoreSentencesInChapter? no → hasMoreChapters? yes
   fetchNextChapter() → 拿到新 chapter 的 sentences
   ▼ await ttsService.speakSentence(firstSentenceOfNextChapter, idx)
[ZhiYueTtsService] tts.speak(next)（service 持续 active）
   同时 updateMediaSessionMetadata(newChapterTitle, ...)（锁屏/通知更新）
```

### 2.6 电话打断

```
[PhoneStateListener / TelephonyCallback] CALL_STATE_RINGING
   ▼
[ZhiYueTtsService._onPhoneRinging]
   autoPause()（记录位置 + tts.stop + state PAUSED）
   **不**调 stopForeground（FGS 保活，挂电话后可 resume）
   ▼
[EventChannel] emit {event:"state", state:"paused", reason:"phone"}

[用户接听 → 通话结束]
   **不**自动 resume（让用户主动点，避免打扰）
   配置项：ttsSettings.autoResumeAfterPhoneCall，默认 false
```

### 2.7 蓝牙耳机 / 锁屏按键

```
[Bluetooth headset] 按 play/pause/skip
   ▼
[Android 系统] 路由到 MediaSession
   ▼
[MediaSession.Callback.onPlay / onPause / onSkipToNext]
   ▼
[ZhiYueTtsService] 内部调 drivePlay / drivePause / driveSkipToNext
   （不走 MethodChannel，避免 recursion）
   ▼
[EventChannel] emit state 变化
   ▼
[Dart] TtsPlaybackController 收到新 state，UI 同步
```

### 2.8 通知栏「关闭」按钮

```
[Notification action: "STOP"] → [ZhiYueTtsMediaButtonReceiver]
   ▼ startService(STOP intent)
[ZhiYueTtsService] 走 2.4 stop 流程
```

## 错误处理

### init 阶段

| 失败 | 处理 |
|---|---|
| `TextToSpeech` ctor `onInit` 失败（精简版 ROM 无 TTS engine） | MethodChannel 返回 `{error: "TTS_UNAVAILABLE"}` → Dart 抛 `TtsUnavailableException` → UI SnackBar「本机未安装 TTS 引擎，请在系统设置→辅助功能中开启」 |
| Language missing（中文书但 TTS engine 无 zh-CN 语音包） | 返回 `{error: "LANGUAGE_MISSING", lang: "zh-CN"}` → UI 引导去系统 TTS 设置下载（deeplink `android.settings.ACTION_TTS_SETTINGS`） |
| `startForegroundService` 拒绝（`ForegroundServiceStartNotAllowedException`，Android 12+） | 用户在后台非 user-gesture 触发（如跨章自动播放时 app 切到后台）。Catch + fallback：用 `flutter_local_notifications` 显示普通通知，TTS 继续播放直到 OS 回收进程。EventChannel emit `{event:"warning", code:"BG_PLAY_DEGRADED"}` |
| MethodChannel 注册失败（plugin 未注册） | Dart `MissingPluginException` → catch + log，UI 报「TTS 模块未加载，请重启 app」 |

### speak 阶段

| 失败 | 处理 |
|---|---|
| `tts.speak()` 返回 ERROR（synthesize 失败） | service 记录 utteranceId，emit `{event:"error", utteranceId, code}` → Dart 跳过该句继续下一句 |
| Service 被系统 kill（低内存） | 重启后 `ZhiYueTtsPlugin` 检测 service 未运行 → 下次 speak 重新走 init 流程（lazy）。Dart 侧记录 `last_tts_position` 用于「从上次位置继续」提示 |
| AudioFocus loss（其他 app 抢占焦点） | 自动 pause（不 stop），emit `{event:"state", state:"paused", reason:"focus_loss"}`。不自动 resume |
| 蓝牙耳机断开（BecomingNoisy） | 自动 pause（避免突然外放） |

### 资源生命周期

| 资源 | 申请 | 释放 |
|---|---|---|
| `TextToSpeech` | `ZhiYueTtsService.onCreate` | `onDestroy` |
| `MediaSessionCompat` | `onCreate` | `onDestroy` + `isActive=false` |
| `AudioFocusRequest` | `onCreate` | `onDestroy` 调 `abandonAudioFocus` |
| `PhoneStateListener` / `TelephonyCallback` | `onCreate` | `onDestroy` unregister |
| Foreground notification | `startForeground` 在 `onCreate` 末尾 | `stopForeground(true)` 在 STOP intent |
| Service 本身 | `startForegroundService` | `stopSelf()` 在 STOP intent |

**双重保险**：
- `ZhiYueTtsPlugin.onDetachedFromEngine`（app 关闭时 Flutter 触发）发 STOP intent 给 service，确保即使 Dart 侧没显式 stop，service 也会被清理
- `ZhiYueTtsService.onTaskRemoved`（用户从 recent tasks 滑掉 app）调 stopSelf

## Fallback 策略（方案 2 → 方案 1）

### 触发条件

v1.13 release build 在真机（荣耀 / 小米 / 华为鸿蒙前 / OPPO / vivo）启动时复现 crash，且根因分析指向 manifest FGS 声明（不是 plugin attach-time work，因为我们已经保证 `onAttachedToEngine` 空）。

### 实现方式：Build Flavor

不能用 runtime toggle，因为 manifest 在 APK 安装时就被 OS 扫描。

`android/app/build.gradle.kts`：

```kotlin
android {
    flavorDimensions += "fgs"
    productFlavors {
        create("withFgs") {
            dimension = "fgs"
            // 默认 flavor，含 FGS 声明（方案 2）
        }
        create("noFgs") {
            dimension = "fgs"
            // Fallback flavor，无 FGS 声明（方案 1）
        }
    }

    sourceSets {
        getByName("withFgs") {
            manifest.srcFile("src/with-fgs/AndroidManifest.xml")
        }
        getByName("noFgs") {
            manifest.srcFile("src/no-fgs/AndroidManifest.xml")
        }
    }
}
```

两份 manifest：

```
android/app/src/main/AndroidManifest.xml          ← 共享部分（权限、activity 等）
android/app/src/with-fgs/AndroidManifest.xml      ← 含 <service foregroundServiceType="mediaPlayback"> + FOREGROUND_SERVICE_MEDIA_PLAYBACK 权限
android/app/src/no-fgs/AndroidManifest.xml         ← 空（或仅含 flutter_local_notifications 相关）
```

构建命令：
- 默认（推荐路径，方案 2）：`flutter build apk --flavor=withFgs`
- Fallback（如果验证发现 crash）：`flutter build apk --flavor=noFgs`

### Fallback 功能影响

| 功能 | withFgs | noFgs |
|---|---|---|
| 通知栏控件 | FGS mandatory notification | `flutter_local_notifications` 普通通知 |
| 后台播放 | ✅ | ❌ |
| 锁屏控件 | ✅ | ❌ |
| 蓝牙按键 | ✅ | ✅（MediaSession 不需 FGS 也能注册） |

### 灰度发布

v1.13.0-alpha 三个变体并行发布到 Gitee Release：
- `zhiyue-1.13.0-alpha-with-fgs.apk`（推荐，全功能）
- `zhiyue-1.13.0-alpha-no-fgs.apk`（保险）

用户反馈：哪一台机型 + 哪个 variant crash？

- 若 with-fgs 在某些机型 crash 而 no-fgs 不 crash → 永久放弃 FGS 路线，所有用户用 no-fgs
- 若 with-fgs 在所有机型都不 crash → no-fgs variant 后续版本下线

## 风险与开放问题

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| Manifest FGS 声明在国产 ROM 触发启动 crash（与 v1.12.2-alpha 经验冲突，但当时是 plugin 注册未跳过） | 中 | C/D 不交付 | Build flavor 提供 noFgs fallback；真机测试 P0 验证 |
| `TextToSpeech` 在某些精简版 ROM 上 ctor 失败 | 低 | A 不交付该机型 | `TtsUnavailableException` 优雅降级 + UI 引导 |
| Android 12+ `startForeground` 5 秒 ANR 阈值（罕见，正常流程 < 100ms） | 低 | service crash | `onCreate` 内只做同步轻量构造，重活放 `onStartCommand` |
| 蓝牙耳机 BecomingNoisy 行为差异（部分 ROM 不发该广播） | 低 | 用户摘耳机后突然外放 | 同时监听 `ACTION_AUDIO_BECOMING_NOISY` + `AudioManager.ACTION_HEADSET_PLUG` 双保险 |
| PhoneStateListener 在 API 31+ deprecated | 中 | 编译警告 + 未来 break | API 31+ 用 `TelephonyCallback`，老 API 用 `PhoneStateListener`，Build.VERSION 分支 |
| FGS manifest placeholder / source set 与其他 plugin manifest 冲突 | 低 | build 失败 | manifest merger log 排查；最坏情况手工合并 |

### 开放问题（v1.13 实现时再决定）

1. resume 时从断点精确续读 vs 从当前句首重读？audio_service 是当前句首重读，可接受。若用户要求精确续读，需用 `tts.playEarcon` + silence 插入 trick。
2. 通知栏 custom layout（带封面图）vs 系统默认 MediaStyle？默认 MediaStyle 兼容性最好，先实现，custom 延后。
3. 多本书的 MediaSession queue（一次只读一本，不需要 queue，YAGNI）。
4. WearOS / Android Auto 集成（明确不在 v1.13 范围）。

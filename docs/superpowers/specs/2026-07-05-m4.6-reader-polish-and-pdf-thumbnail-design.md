1. **G1（#1）** PDF 在宽屏（≥1100px）自动启用双页，与 EPUB 行为对齐；窗口缩窄回单页。
2. **G2（#2）** PDF 无内嵌目录时，目录 tab 显示页面缩略图 grid，点击可跳转。

## 根因分析（bug 类：#5 / #6）

### Bug #5 — Markdown 段落堆叠

**现象**：原 MD 文档分段一行一行，阅读器里打开后段落堆叠在一起，没有还原 markdown 换行格式。

**根因链**：
- `markdown_book_loader.dart:93,100` 调 `md.markdownToHtml(body)` 时**未传任何 extensionSet / 自定义语法**。
- markdown 包（7.3.1）按 CommonMark 规范处理换行：
  - 段落内单个 `\n` 是 **soft break**（`soft_line_break_syntax.dart:13-21`），渲染成普通文本 `\n`，**不**变 `<br>`。
  - 只有两个空格结尾的行（`  \n`）或反斜杠结尾（`\\\n`）才是 **hard break**，转 `<br>`（`line_break_syntax.dart:11`）。
- 下游 `flutter_widget_from_html` 的 HtmlWidget 把文本节点里的 `\n` 当 HTML whitespace 折叠成空格。
- 结果：用户写的
  ```
  第一行
  第二行
  第三行
  ```
  （无空行）→ `<p>第一行 第二行 第三行</p>`，三行视觉上堆成一行。

**修复方向**：调 `markdownToHtml` 时启用 GFM 的 `LineSplitExtension`，把每个 soft break 渲染成 `<br>`。这是 markdown 包官方内置扩展（`package:markdown/src/html_renderer.dart` 已注册），不破坏既有 `#`/`##` 切章、列表、代码块等语法。

### Bug #6 — TXT 内容溢出屏幕外

**现象**：TXT 文档打开后内容都跑到屏幕外。

**根因链**：
- `text_book_loader.dart:62` 用 `text.split(RegExp(r'\n\s*\n'))` 按空行切分段落。
- 中文小说 TXT 标准格式是**连续行无空行**（每行一段，仅行尾 `\n`），`split` 返回**单元素列表**——整篇当一个块。
- `text_book_loader.dart:68-72` 把这个超大块包成一个 `<p>...</p>`（内部用 `<br>` 连接所有行）。
- Paginator（`paginator.dart:63-120`）通过 `HtmlUtils.htmlToParagraphs` 按 `<p>` 切段测高。**整篇一个 `<p>`** = 单段超长文本，单段内 TextPainter 测出超长高度，分页 break 在段内发出但 `HtmlSlicer.sliceByPlainRange` 切出的 HTML slice 仍含整个 `<p>` 容器 → 渲染出的 HtmlWidget 把整个 `<p>` 当一个连续流，**溢出视口**。
- M4.5 测试 `markdown_book_loader_test.dart:113-121` 用例都用了空行分隔（`'第一段\n\n第二段'`），所以测试通过但实际中文小说触发退化。

**修复方向**：智能启发式分段——
- 有空行：保留空行作为段落分隔（兼容原有格式）。
- 无空行：连续行视为独立段落（中文小说每行一段是事实标准）。
- 短行（≤2 字 / 全标点）：视为分隔/标题，独立成段。

## Architecture Decisions

### A1：PDF 双页与 EPUB 双页保持独立（不抽象统一）

PDF 已有 `_buildDualPage`（`pdf_renderer.dart:293-345`，两个 `PdfViewer` 并排），EPUB 用 `_DualSpreadAligner` + 单 PageView 折半。两者底层 widget 完全不同（pdfrx native vs fwfh HtmlWidget）。

**决策**：M4.6 只在 `reader_body.dart:385-402` 的 LayoutBuilder 里给 PDF 加一行 `pdfEngine.dualPageMode = isWide`，**不**抽象公共接口。理由：R1 风险——改 1211 行 `epubx_renderer.dart` 抽 base class 风险远大于收益，PDF 双页已稳定运行。

### A2：缩略图用 pdfrx `PdfPage.render()` + 内存 LRU + GridView 懒加载

PDF 134 页 × ~200KB/页 ≈ 27MB，全量渲染会爆内存。

**决策**：
- 缓存：内存 LRU（容量 32 张，~6MB），超出淘汰最旧。
- 加载策略：`GridView.builder` 只构建可视区 + 前后各 5 个 cell；每个 cell 进入可视区才触发 `page.render()`，离开后图片可被 LRU 淘汰。
- 渲染尺寸：缩略图宽度 200px（约实际页宽的 1/4），高度按 PDF 页原比例。
- 并发：单线程串行渲染（pdfrx 内部已串行化，无需额外锁）。

### A3：淡绿主题用「浅艾绿 #E3EDD7」单值，文字色 #3A4A2D

用户在色值选项中选了"浅艾绿 #E3EDD7"（偏黄绿的淡色，护眼纸感）。文字色配套用深褐 #3A4A2D（对比度足够，WCAG AA 通过）。

**决策**：枚举名 `ReadingTheme.green`，UI 标签 "绿"，EPUB fg/bg = `(0xFF3A4A2D, 0xFFE3EDD7)`，PDF ColorFilter 用 `ColorFilter.mode(0x??E3EDD7, BlendMode.dstATop)`（半透明叠加，仿 sepia 模式）。

### A4：默认字体迁移用 DB schema upgrade hook

老用户的 `TypographyProfile` 是 DB 独立记录（`typography_profile_repository.dart`），改 `TypographySettings.defaults()` 不会动 DB。

**决策**：在 drift DB 的 schema 升级里加一个 migration step（从当前 schemaVersion +1）：`UPDATE typography_profiles SET font_family = 'LXGWNeoXiHei' WHERE font_family IS NULL`。一次性、幂等（重跑无副作用，因 WHERE 条件过滤已迁移行）。

### A5：TXT 智能启发式分段规则

```
对原文按 \n 切行 → lines[]
遍历 lines：
  - 行 trim 后为空（含纯空格/制表符） → 段落分隔符（结束当前段，不输出 <p>）
  - 行 trim 后长度 ≤ 2 或全是标点 → 视为"短行"（标题/分隔），独立成 <p>
  - 否则（长行） → 累积到当前段 buffer
  - 当遇到空行或短行边界 → 把当前 buffer 里的连续长行**每行单独成 <p>**
    （中文小说"每行一段"事实标准）
最终：所有 <p> 拼接，每段独立分页
```

关键：**长行不合并**（避免重蹈 Bug #6 覆辙——一旦合并就可能产生超长 `<p>`），每行独立 `<p>` 保证 Paginator 能正常分页。空行分隔的原文也兼容（每个非空长行独立 `<p>`，视觉效果与原"按空行切"一致）。

### A6：Markdown 启用 LineSplitExtension

`md.markdownToHtml(body, extensions: [LineSplitExtension()])`。这是 markdown 包内置扩展（`package:markdown/src/inline_syntaxes/soft_line_break_syntax.dart` 的姊妹实现），无需额外依赖。其他 GFM 扩展（表格/删除线）本次不开，避免引入未测试行为。

## Risks

| 风险 | 等级 | 缓解 |
|---|---|---|
| R1：PDF 双页自动切换与 `isScanned` FutureBuilder 时序冲突（pdf_renderer.dart:244-253 已知） | 中 | 在 `setDualPageMode` setter 内加 `if (!_isScannedResolved) return;` 防御，等 FutureBuilder 解析完再切。回归测试覆盖。 |
| R2：缩略图 grid 在超大 PDF（500+ 页）下首次渲染慢 | 中 | LRU + 懒加载（A2）；grid 只渲染可视区；首次进入 tab 显示 loading + 已渲染的渐进出现。 |
| R3：枚举扩展后老 DB 反序列化 `byName` 抛错（旧记录不可能含 `green`，无风险） | 低 | 已确认 `typography_settings.dart:102` 的 `byName` 对未知值抛错——但老 DB 行不会含 `green`，无影响。新增枚举值只在新选择后写入。 |
| R4：DB migration 在已有 'LXGWNeoXiHei' 或非 null 字体的预设上误改 | 低 | migration SQL `WHERE font_family IS NULL` 严格过滤，已迁移/已自定义的行不动。 |
| R5：LineSplitExtension 影响 MD 代码块/列表渲染 | 低 | LineSplitExtension 只处理 paragraph 内的 soft break，代码块（`<pre><code>`）和列表（`<ul><li>`）走自己的 block syntax，不受影响。回归测试覆盖代码块/列表用例。 |
| R6：TXT 启发式把英文长段落（一空行内多句）逐行拆散 | 低 | 中文小说场景为主；英文连续长行（无 \n）仍当一个 `<p>`；英文每行一句的情况会被拆，但视觉上每行独立 `<p>` 也合理（加段间距）。 |

## 1. 目标

把目前散落在 5 个入口的 AI 功能（书卡菜单 / 详情页 / Reader AppBar ×2 / 选区工具栏）整合为**一个右侧抽屉**，以"每书多会话"模型组织对话，subagent 模式隔离预设调用避免上下文污染。

### 1.1 用户面目标

| # | 目标 | 验证 |
|---|------|------|
| G1 | 所有 AI 交互集中到阅读页右侧抽屉 | 现有 5 个 AI 入口全部移除/改造，统一从抽屉进入 |
| G2 | 每本书可拥有多个独立会话 | 下拉切换、`/new` 新建、`/del` 删除、`/clear` 清空 |
| G3 | 预设调用（卡片 + slash）走 subagent，不污染当前对话上下文 | Card 1/`/chapter` 调用后，下一条用户自由消息看不到 chapter prompt，但看得到 chapter 结果 |
| G4 | 选区文本不自动发送，落到输入框由用户修订后发送 | 选区工具栏 "提问 AI" → 输入框插入 `> 原文`，不调 LLM |
| G5 | 苏格拉底模式：AI 主动基于本章内容提问，多轮对话 | Card 2 / `/socratic` 启动 → 自动章节回顾 bootstrap → AI 反问 |
| G6 | `@` 笔记 mention：把书中笔记作为 context 附加到消息 | 输入框 `@` 弹笔记清单 → 选中 → block quote 插入 |
| G7 | 全部会话/消息本地持久化 + 同步前置 schema | `chat_sessions` + `chat_messages` 表，含 `updated_at` + `deleted_at` |
| G8 | 现有"导入即批处理（BookPreprocessor）"暂时注释掉 | 导入流程不再触发；表与代码保留以备未来恢复 |

### 1.2 不做（明确否决）

- ❌ **整书导读 `/full`**：开销大、长书超 LLM context window（用户 2026-07-06 决定）
- ❌ **成本/token 估算 UI**：roadmap §3 Spiral 4 于 2026-06-29 被否决
- ❌ **跨设备同步**：本 spiral 只做 schema 前置，sync 留 M2.8+
- ❌ **苏格拉底模式的"自动收束"**：用户没要求 AI 检测疲劳自动收尾，YAGNI
- ❌ **`/translate` `/explain` `/questions` 等新预设**：v1 只 ship `/chapter` `/socratic` `/recap`，其他延后
- ❌ **Card 2 之外的功能**：Card 2 = 苏格拉底启动，已确定；其他卡片型预设延后
- ❌ **云端会话搜索**：跨会话搜索是 phase 3+，本 spiral 只做单会话内 scrollback

### 2.3 核心边界（强制实现 point 9 的物理隔离）

**Subagent use case 必须遵守**：
- 只接受 `(bookId, chapterIndex, [...additional context])` 作为输入
- **不读** `ChatSessionController` 的状态
- **不写** 当前 session 的 `messages` 列表（只通过 Repository 写一条 AI 消息）
- 输出：`Stream<String>`（流式）+ 最终 `ChatMessage` 行（持久化）

这意味着 `RunChapterGuideUseCase` 完全不知道当前会话有谁、用户之前问过什么 —— 它只是跑 LLM、把结果写一条 message 进当前 session。隔离自然实现。

## 3. 数据模型

### 3.1 新增表（Drift schema 迁移）

```dart
// lib/data/local/tables/chat_sessions.dart
class ChatSessions extends Table {
  TextColumn get id => text()();                              // UUID v4
  TextColumn get bookId => text().customConstraint('REFERENCES books(id) ON DELETE CASCADE')();
  TextColumn get title => text()();                           // 自动 = 首 20 字 / "新会话 yyyy-MM-dd HH:mm"
  TextColumn get mode => text().withDefault(const Constant('normal'))();  // 'normal' | 'socratic'
  DateTimeColumn get createdAt => dateTime()();
  DateTimeColumn get updatedAt => dateTime()();
  DateTimeColumn get deletedAt => dateTime().nullable()();

  @override
  Set<Column> get primaryKey => {id};
}

// lib/data/local/tables/chat_messages.dart
class ChatMessages extends Table {
  TextColumn get id => text()();                              // UUID v4
  TextColumn get sessionId => text().customConstraint('REFERENCES chat_sessions(id) ON DELETE CASCADE')();
  TextColumn get role => text()();                            // 'user' | 'ai' | 'system'
  TextColumn get content => text()();
  TextColumn get presetSource => text().nullable()();         // 'card.chapter' | 'card.socratic' | '/chapter' | '/socratic' | '/recap' | null
  TextColumn get attachmentNoteId => text().nullable()();     // REFERENCES book_notes(id) — nullable, soft ref
  TextColumn get attachmentNoteSnapshot => text().nullable(); // immutable snapshot at send time
  DateTimeColumn get createdAt => dateTime()();
  DateTimeColumn get updatedAt => dateTime()();
  DateTimeColumn get deletedAt => dateTime().nullable()();

  @override
  Set<Column> get primaryKey => {id};
}
```

### 3.2 索引

```sql
CREATE INDEX idx_chat_sessions_book ON chat_sessions(book_id, deleted_at);
CREATE INDEX idx_chat_messages_session ON chat_messages(session_id, created_at);
CREATE INDEX idx_chat_messages_pending_sync ON chat_messages(updated_at) WHERE deleted_at IS NULL;
-- 第三个索引预留给未来 sync 推送 outbox 用
```

### 3.3 同步前置字段（不本 spiral 实装 sync，但 schema 准备好）

所有表带 `updated_at` + `deleted_at`：
- `updated_at`：每次写入/修改递增
- `deleted_at`：软删除标记，`NULL` = 活；非 NULL = 已删（同步时跳过实体内容、只同步墓碑）

未来 M2.8 sync 落地时：
- outbox 表追加 chat_sessions / chat_messages 的变更事件
- conflicts 解决仍按 last-write-wins（`updated_at` 比较）

### 3.4 迁移策略（schema vN → vN+1）

```dart
// schema_v<N+1>_migration.dart
await m.addColumn(chatSessions, chatSessions.deletedAt);
await m.addColumn(chatMessages, chatMessages.attachmentNoteId);
// ...
await m.customStatement('CREATE INDEX idx_chat_sessions_book ...');
```

**用户已有的 `qa_history` 数据**：用户决定清空。迁移时直接 `DROP TABLE qa_history`，新建 `chat_sessions` + `chat_messages`。`ai_summaries` 表保留（subagent 调用仍用其缓存）。`book_passages` 表保留为空（BookPreprocessor 注释掉后不再写入，但表结构保留以备未来恢复）；`BookQaService` 在 M2.7 后不再被任何 UI 触发，代码保留但退役。

### 3.5 BookPreprocessor 暂时注释

不删表、不删代码。在 `BookImportService.import()` 调用 `BookPreprocessor.start()` 处用 `// M2.7: disabled per user request 2026-07-06` 注释掉。`book_passages` 表保留为空，`BookQaService` 因新方案不再调用也跟着退役（保留代码）。

### 4.5 AiInputComposer（输入框 + @ + /）

```
┌────────────────────────────────────────────────┐
│ [@笔记]                                          │
│ ┌──────────────────────────────────────────┐   │
│ │ > 📝 [笔记标题]                           │   │  ← @ 插入的笔记 block quote
│ │ > 笔记的前 200 字预览...                   │   │
│ └──────────────────────────────────────────┘   │
│                                                  │
│ ┌──────────────────────────────────────────┐   │
│ │ 输入消息...                       [/] [@] │   │  ← 主输入框
│ └──────────────────────────────────────────┘   │
└────────────────────────────────────────────────┘
```

**`/` 触发**：
- 用户在空输入框敲 `/` → 弹出 popup（位置紧跟光标下方）
- 列出（普通模式）：`/new` `/clear` `/del` `/chapter` `/socratic` `/recap` `/help`
- 列出（苏格拉底模式）：上述 + `/exit-socratic`（仅当 `session.mode == 'socratic'` 时显示）
- 边输入边过滤（例如 `/cl` 过滤出 `/clear`）
- 选中后 = 等价于回车提交该 slash 命令；不会留在输入框作为文字

**`@` 触发**：
- 用户敲 `@` → 弹出 popup 列出本书所有笔记（标题 + 前 60 字预览 + updated time）
- 输入 `@xxx` 边输入边过滤标题
- 选中后：
  - popup 关闭
  - 输入框上方追加一条 block quote 预览（标题 + 前 200 字）
  - `@xxx` 文字从输入框移除
  - 内部状态：`pendingAttachment = (noteId, snapshot)`（**单条消息限 1 个附件**，第 2 次 `@` 弹 toast "已替换附件" 并覆盖）
- 单附件限制原因：避免 schema 复杂化（无需子表）；多笔记场景用户可分多条消息发送

**发送按钮**：
- 输入框空 + 无 pending attachments → 禁用
- 点发送：
  - 调 `SendMessageUseCase(text: text, attachments: pendingAttachments, sessionId: current)`
  - pendingAttachments 清空
  - 输入框清空

### 4.6 选区 → AI 输入框（point 11）

Reader 选区工具栏现有 "AI 点评" 按钮改为 **"提问 AI"**：
- tap → 不立即调 LLM
- 行为：
  1. 自动唤出右抽屉（wide 模式 panel 已展开则忽略；narrow 模式则 `scaffoldKey.currentState.openEndDrawer()`)
  2. 把选中文本以 `> {selectedText}` 形式插入输入框（保留光标在末尾，用户继续敲问题）
  3. 不调 LLM
- 如果当前 session 是 socratic 模式：弹确认 "当前在苏格拉底模式，切换到普通会话再问？" —— 避免苏格拉底语境下答非所问

## 5. 关键流程

### 5.1 用户自由消息（normal 模式）

```
1. 用户在输入框敲 "金圣叹怎么评武松？" → 点发送
2. AiInputComposer 调 SendMessageUseCase
3. UseCase:
   a. ChatRepository.insertMessage(ChatMessage(
        id: uuid(), sessionId: current, role: 'user',
        content: '金圣叹怎么评武松？', createdAt: now))
   b. ChatSessionController.messages 刷新（流式增量）
   c. 取当前 session 所有未删消息（按 createdAt ASC）
   d. PromptBuilder.chat(messages) → 完整 prompt
   e. OpenAiCompatibleClient.streamChat(prompt)
   f. 流式 token → 增量写入新 AI message 行（每 200ms flush 一次避免 DB 抖动）
   g. 完成时最终 flush + 更新 updated_at
4. 流结束 → UI 显示完成态
```

**Context 模型（确认 B）**：每次取**全量历史**塞进 prompt（用户 /clear 或 /new 控制大小）。

### 5.2 Card 1 / `/chapter`（subagent）

```
1. 用户 tap Card 1
2. AiPresetCardRow 调 RunChapterGuideUseCase(bookId, chapterIndex)
3. UseCase（与 ChatSessionController 状态隔离）:
   a. AiSummaryCache.get(bookId, mode='chapter', sourceHash=hash(chapterText))
      → 命中：返回缓存文本，跳到 step e
      → 未命中：继续
   b. PromptBuilder.chapter(chapterText) → prompt
   c. OpenAiCompatibleClient.streamChat(prompt)
   d. 流式 token 累积成完整 result string
   e. AiSummaryCache.put(bookId, mode='chapter', sourceHash, result)
   f. ChatRepository.insertMessage(ChatMessage(
        id: uuid(), sessionId: currentSessionId, role: 'ai',
        content: result, presetSource: 'card.chapter', createdAt: now))
   g. 流式 token 同步增量更新 UI（让用户看到生成进度）
4. UI 显示新 AI 消息 + 流式追加
```

**关键**：step 3a-3e **不读 currentSession 的 messages** —— prompt 只含 chapter 内容，不含会话历史。下次用户自由消息时，会看到这条 AI 消息作为上下文，但看不到 chapter prompt（即 point 9 隔离）。

### 5.3 Card 2 / `/socratic`（subagent + mode switch）

```
1. 用户 tap Card 2 / 敲 /socratic
2. 触发 SwitchSessionModeUseCase(currentSession, 'socratic')
   - 如果当前 session 已有 messages 且 mode=normal：
     询问"切换到苏格拉底模式？后续对话 AI 会用苏格拉底导师语气"
     确认 → 更新 chat_sessions.mode = 'socratic' + 写一行 system message "苏格拉底模式启动"
   - 如果当前 session 是空的：直接切换，无确认
   - 如果当前 session 已是 socratic：no-op
3. 触发 RunSocraticBootstrapUseCase(bookId, chapterIndex)
   a. AiSummaryCache.get(bookId, mode='recap', sourceHash=hash(chapterText))
      命中：用缓存；未命中：调 BookReviewer (M2.1) 生成章节回顾
   b. PromptBuilder.socraticBootstrap(recap) → prompt
      "你是苏格拉底式导师。下面是本章回顾：{recap}。
       请基于其中一点，向学生提一个开放性问题。
       不要直接讲解。"
   c. OpenAiCompatibleClient.streamChat(prompt)
   d. 结果写入 ChatMessage(role='ai', presetSource='card.socratic')
4. 后续自由消息走 SendMessageUseCase，但 PromptBuilder.chat 检测 session.mode='socratic'
   → 加 socratic system prompt 前缀（持续追问、不直接回答、引导思考）
5. 退出苏格拉底：
   - /new 新建会话 → 新 session mode='normal'
   - /exit-socratic → 当前 session 切回 normal mode（无新 session）
```

### 5.4 `/recap`（subagent，无 mode 切换）

```
1. 用户敲 /recap
2. AiSlashAutocomplete 路由到 RunRecapUseCase(bookId, chapterIndex)
3. UseCase:
   a. AiSummaryCache.get(bookId, mode='recap', sourceHash)
   b. 未命中 → BookReviewer.runRecap(bookId, chapterIndex) (M2.1 既有逻辑)
   c. 结果写入 ChatMessage(role='ai', presetSource='/recap')
4. 当前 session mode 不变（不进苏格拉底）
```

### 5.5 `@` 笔记 mention

```
1. 用户在输入框敲 "@金"
2. AiInputComposer 监听 TextEditingController，检测 "@xxx" 模式
3. 弹出 popup 列出 book_notes 表中 title LIKE '%金%' 的笔记
4. 用户选中"金圣叹点评笔记"
5. AttachmentNoteResolver.resolve(noteId):
   a. BookNotesDao.findById(noteId) → BookNote row
   b. snapshot = note.content (TEXT 完整快照)
   c. pendingAttachment = PendingAttachment(noteId, title, snapshot)
      （若已有 pendingAttachment，先 clear 再 set，弹 toast "已替换附件"）
6. UI:
   a. 输入框上方插入 block quote 预览（标题 + 前 200 字）
   b. 输入框的 "@金" 文字移除
   c. 光标保持在原位
7. 用户继续敲问题
8. 用户点发送：
   a. SendMessageUseCase 收到 (text, pendingAttachment?)
   b. ChatRepository.insertMessage(ChatMessage(
        id: uuid(), sessionId: current, role: 'user',
        content: text,
        attachmentNoteId: pendingAttachment?.noteId,
        attachmentNoteSnapshot: pendingAttachment?.snapshot,
        createdAt: now))
   c. 实际发送给 LLM 时：把 snapshot 拼在 user content 前
      "{snapshot}\n\n用户问题: {text}"
   d. pendingAttachment 清空，输入框清空
```


## 6. 错误处理

### 6.1 LLM 调用失败

```
网络断 / API 错误 / Rate limit:
1. UseCase 捕获异常
2. 写入 ChatMessage(role='ai', content='⚠️ 调用失败：{errorMessage}',
                    presetSource='error')
3. UI 显示红色错误消息 + "重试" 按钮
4. 重试 → 重新触发 UseCase（带原 user message 的 id 做幂等检查）
```

### 6.2 流式中断

```
Token 流到一半断连:
1. 已写入的部分内容保留为 ChatMessage（content 含已收到的部分）
2. 在末尾追加 "\n\n⚠️ 生成中断"
3. UI 显示重试按钮（重新调 UseCase → 覆盖写新 ChatMessage，旧的不删）
```

### 6.3 章节文本获取失败

```
RunChapterGuideUseCase 需要 chapterText，但 ChapterTextProvider 抛异常:
1. UseCase 抛 ChapterUnavailableException
2. UI: Card 1 显示错误 toast "无法获取本章文本"
3. 不写入 ChatMessage
```

### 6.4 会话并发

```
同一 session 在两个窗口同时操作（unlikely 但要防）:
- ChatRepository 所有写操作用 transactions
- updated_at 服务端处理冲突（last-write-wins）
- UI 不做乐观锁；刷新时直接覆盖本地状态
```

## 9. 风险 & 决策记录

| 风险/决策 | 选择 | 理由 |
|---|---|---|
| 上下文模型 B vs C | B（全量历史） | 用户决定，C 留作未来无缝升级（schema 不变） |
| BookPreprocessor | 注释掉、保留代码+表 | 用户决定，未来可恢复 |
| 整书导读 `/full` | 暂缓 | 开销 + context limit |
| 苏格拉底退出方式 | `/new` 自动 + `/exit-socratic` 手动 | 两种途径覆盖不同心智模型 |
| 笔记 mention 用 snapshot | 是 | 历史不可变性 + 同步友好 |
| Card 2 = 苏格拉底 | 是 | 用户决定，苏格拉底是高价值差异化功能 |
| 单消息单附件 | 是（schema 简化） | 多附件通过拆多条 'user' 消息实现 |
| 会话 title 自动生成 | 首条用户消息前 20 字 | 免用户起名负担，长按可重命名 |
| Drawer 触发 | AppBar toggle icon | 跟现有左抽屉对称 |
| `/chapter` 是否在 slash 列表 | 是 | Card 1 = 视觉快捷，slash = 键盘快捷，两者等价 |
| 单消息单附件 | 是（schema 简化） | 多附件通过拆多条 'user' 消息实现；附件多时 UI 自动堆叠多个 block quote |
| `/exit-socratic` 仅 socratic 模式显示 | 是 | 普通模式下该命令无意义，autocomplete 中隐藏；用户手敲会被识别为未知命令并提示 |
| 苏格拉底 `system prompt` | "你是苏格拉底式导师，不直接给答案，反问、追问、引导" | 写在 PromptBuilder，未来可调 |
